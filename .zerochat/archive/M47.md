## M47 Server-side background turn execution and conversation continuation (--conversation)

Goal: zerochat.py supports continuing an existing SQLite conversation via --conversation <id> while writing live run status to ~/zerochat/runs/<conversation_id>.json, and connected clients with a general profile (Z-*) selected can toggle "Run on server" in the top header to execute agentic turns in the background on the server, follow 1s heartbeat progress on the focused chat while freely switching sessions, see running (clock) and needs-input (?) indicators in the sidebar history even after closing and reopening the browser, and resume paused ask_user or tool permission requests by launching a new --conversation run (full specification in docs/m47-server-runs.md).
Done when: --conversation <id> loads and updates a stored SQLite conversation and writes live progress/state to ~/zerochat/runs/<conversation_id>.json, ask_user and unapproved tool permissions pause the server run cleanly with status needs_input while preserving valid assistant+tool turn boundaries in SQLite, zerochat/run/start and zerochat/run/cancel manage detached server runs, zerochat/heartbeat accelerates to 1s during active runs returning lightweight run states plus detailed progress only for focus_conversation_id, the header switch appears only when connected with a Z-* profile, the composer locks only the running conversation while allowing switching/creating other chats, answering a pending question or tool approval relaunches --conversation <id>, and passing test:architecture, test:infrastructure, test:unit, test:integration, and test:browser.
