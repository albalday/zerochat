Usar el servidor de casa desde Android

Un túnel SSH lleva las herramientas del equipo de casa al navegador de la tablet o el móvil.

1. Cómo funciona

La interfaz se carga desde GitHub Pages en el navegador de Android y habla con 127.0.0.1:6883 de la propia tablet. El cliente SSH (ConnectBot o Termux) redirige ese puerto al 127.0.0.1:6883 del equipo de casa, donde corre el servidor local. Así, archivos, comandos y servicios MCP son los de casa.

  • Sin exponer ZeroChat: el servidor sigue escuchando solo en 127.0.0.1; lo único accesible desde fuera es SSH.
  • Puerto 6883: distinto del 6388 por defecto, para que convivan el ZeroChat del escritorio y el de la tablet.
  • Modelo en casa: si usas LM Studio u otro servidor de modelos en el mismo equipo, redirige también su puerto (1234 en LM Studio) y apunta el perfil a http://127.0.0.1:1234/v1.

2. Preparar el equipo de casa

Endurecer sshd

En /etc/ssh/sshd_config (o un fichero en /etc/ssh/sshd_config.d/), solo claves y solo tu usuario; después reinicia el servicio (sudo systemctl restart sshd):

PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
AllowUsers usuario
AllowTcpForwarding local

Script de arranque

Guárdalo como ~/bin/zerochat-tablet.sh y dale permisos con chmod 700 ~/bin/zerochat-tablet.sh. Arranca ZeroChat sin navegador (o reutiliza el que ya corre), lee el token diario de ~/zerochat/config/token.json e imprime la URL que hay que abrir en la tablet.

#!/usr/bin/env bash
# Levanta ZeroChat sin navegador en casa (o reutiliza el que ya corre) e imprime
# la URL con el token diario para abrirla en el navegador de la tablet.
# Pensado para ejecutarse desde ConnectBot por SSH (también vale como command= forzado).
set -euo pipefail

PORT="${ZEROCHAT_PORT:-6883}"            # debe coincidir con el puerto redirigido en ConnectBot
DATA_DIR="${ZEROCHAT_DATA_DIR:-$HOME/zerochat}"
TOKEN_FILE="$DATA_DIR/config/token.json"
LOG="$DATA_DIR/tablet-server.log"
ZEROCHAT="${ZEROCHAT_BIN:-zerochat}"
UI_URL="https://albalday.github.io/zerochat/zerochat.html"

read_token() {
    python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["token"])' "$TOKEN_FILE" 2>/dev/null
}

# 200 = servidor ZeroChat con este token; 401 = otro token; 000 = nada escuchando.
probe() {
    curl -s -o /dev/null -w '%{http_code}' --max-time 3 \
        -H "Authorization: Bearer ${1:-x}" "http://127.0.0.1:$PORT/zerochat/heartbeat" || true
}

start_server() {
    echo "Arrancando ZeroChat en 127.0.0.1:$PORT..."
    # --keep-server: el navegador móvil deja de emitir latidos en segundo plano y,
    # sin él, el servidor se cerraría a los 60 s de cambiar de app.
    # setsid + nohup: sobrevive al cierre de la sesión SSH.
    cd "$HOME"
    setsid nohup "$ZEROCHAT" --no-browser --keep-server --port "$PORT" \
        </dev/null >>"$LOG" 2>&1 &
    for _ in $(seq 1 60); do
        sleep 0.5
        token="$(read_token || true)"
        [ -n "$token" ] && [ "$(probe "$token")" = 200 ] && return 0
    done
    echo "ZeroChat no respondió en 30 s. Últimas líneas de $LOG:" >&2
    tail -n 20 "$LOG" >&2
    exit 1
}

token="$(read_token || true)"
case "$(probe "$token")" in
    200) echo "ZeroChat ya estaba en marcha en el puerto $PORT." ;;
    000) start_server ;;
    401)
        # Hay un ZeroChat con un token distinto (p. ej. de ayer y otro proceso renovó token.json).
        echo "El ZeroChat del puerto $PORT usa otro token: lo reinicio."
        pkill -f -- "/zerochat --no-browser --keep-server --port $PORT\$" || true
        sleep 2
        start_server ;;
    *)  echo "El puerto $PORT está ocupado por otro programa." >&2; exit 1 ;;
esac

token="$(read_token)"
url="$UI_URL#token=$token&host=127.0.0.1&port=$PORT"
echo
echo "Abre en la tablet:"
echo "$url"
echo
# Mantiene la sesión abierta (el túnel vive mientras viva la sesión de ConnectBot).
if [ -t 0 ]; then
    echo "Túnel activo. Pulsa Ctrl+C o cierra la sesión para cortarlo (ZeroChat sigue en casa)."
    trap 'exit 0' INT
    while sleep 3600; do :; done
else
    exec sleep infinity
fi
  • Ruta de zerochat: una sesión SSH con orden forzada no carga tu PATH completo. Si zerochat no está en /usr/bin, pon al principio del script su ruta completa, la que muestra command -v zerochat, en ZEROCHAT_BIN.
  • --keep-server: el navegador de Android deja de enviar latidos cuando la pestaña pasa a segundo plano; sin esta opción el servidor se cerraría al minuto de cambiar de aplicación.
  • Registro: la salida del servidor va a ~/zerochat/tablet-server.log.

Clave restringida

Crea un par de claves solo para la tablet y añade la pública a ~/.ssh/authorized_keys con estas restricciones, en una sola línea. Con ella solo se puede abrir el túnel a esos dos puertos y lanzar el script, sin consola ni otras órdenes:

restrict,port-forwarding,permitopen="127.0.0.1:6883",permitopen="127.0.0.1:1234",command="/home/usuario/bin/zerochat-tablet.sh" ssh-ed25519 AAAA… tablet

3. Conectar desde Android

ConnectBot

  1. En las claves públicas de ConnectBot, genera una clave Ed25519 y copia su parte pública al authorized_keys de casa (sección 2).
  2. Crea el host usuario@casa con esa clave.
  3. En las redirecciones de puertos (Port forwards) del host, añade dos de tipo Local: 6883 → 127.0.0.1:6883 y 1234 → 127.0.0.1:1234.
  4. Conecta. La consola muestra la URL; cópiala y ábrela en el navegador. La sesión no admite órdenes: solo mantiene el túnel.

Sin la clave restringida, puedes poner ~/bin/zerochat-tablet.sh en la automatización tras el inicio de sesión (Post-login automation) del host para lanzarlo al conectar.

Termux

Sin -N, para que se ejecute el script y muestre la URL:

ssh -i ~/.ssh/tablet -L 6883:127.0.0.1:6883 -L 1234:127.0.0.1:1234 usuario@casa

En el navegador

  • Acceso a la red local: si el navegador pide permiso para que la página acceda a dispositivos de la red local, acéptalo; sin él no llega a 127.0.0.1.
  • Configuración propia: perfiles, claves API y conversaciones se guardan en el navegador de la tablet, separados de los del escritorio. Crea allí el perfil con el modelo de casa.
  • Token en la URL: quien tenga la URL y el túnel abierto puede usar las herramientas de casa. No compartas la URL.

4. Situaciones habituales

SituaciónQué pasa
ZeroChat ya está en marcha en el 6883El script lo reutiliza y vuelve a imprimir su URL.
El servidor en marcha usa el token de otro díaEl script lo detiene, lo arranca de nuevo con el token del día e imprime la URL nueva. Recarga la página con ella.
Otro programa ocupa el 6883El script termina con error: El puerto 6883 está ocupado por otro programa.
Se corta la conexión SSHZeroChat sigue en marcha en casa. Reconecta y recarga la página. Para pararlo: pkill -f -- '--keep-server --port 6883'.
Las herramientas fallan con 403 Expired or invalid tool authorizationLos relojes de la tablet y de casa difieren en más de 15 s. Activa la fecha y hora automáticas en los dos.
