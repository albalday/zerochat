Servidor local y MCP

Servidor local, servicios MCP y alcance de los permisos.

1. Arranca y conecta

MCP conecta el chat con herramientas del equipo y servicios externos. Necesitas el servidor local de ZeroChat. Elige una forma de instalación:

PyPI (recomendado)

pip install zerochat && zerochat
En Windows: Si el ejecutable zerochat no está en el PATH, arranca directamente con py -m zerochat (o python -m zerochat).

Descarga directa

curl https://albalday.github.io/zerochat/zerochat.py -o zerochat.py ; python3 zerochat.py

Para los siguientes arranques, utiliza zerochat (o py -m zerochat en Windows) o python3 zerochat.py, respectivamente. Ambos abren GitHub Pages y guardan los datos locales en ~/zerochat/.

  1. Mantén el servidor en ejecución y abre el enlace que proporciona.
  2. Ve a Ajustes → MCP y comprueba la conexión y las herramientas descubiertas.
  3. Habilita las herramientas que necesites y revisa sus permisos.

Si aparece desconectado, comprueba que el proceso siga en ejecución, vuelve a abrir su enlace y revisa los permisos de red local del navegador. No hay formulario de conexión manual. No compartas el enlace de arranque que contiene el token.

Compatibilidad de navegador: ZeroChat no es compatible con WebKit (Safari y todos los navegadores de iPhone/iPad). En macOS debería funcionar con Firefox o un navegador basado en Chromium, aunque no se ha probado. Más detalles. Entornos probados: Linux, Windows (PowerShell) y Android (Termux). En Termux no es posible usar Playwright actualmente, así que browser_action y Playwright MCP no están disponibles.

2. Usa las herramientas del equipo

  • Archivos: list_directory, read_file, write_file, edit_file y search_files.
  • Comandos: bash y execute_command. La sesión shell conserva el directorio de trabajo y las variables entre llamadas. En Linux/macOS/Android utiliza bash/sh; en Windows se ejecuta de forma nativa en PowerShell informando del sistema operativo al modelo.
  • Comprobaciones de sintaxis: get_diagnostics; no sustituye las pruebas del proyecto.
  • Navegador: browser_action requiere Node.js y disponer de Chrome o Edge en el sistema (o Chromium). Para usarla, inicia el servicio Playwright en Ajustes → MCP (se instala solo). Consulta la guía de preparación.

Los resultados de herramientas forman parte de la conversación y pueden enviarse al modelo seleccionado.

3. Inicia un servicio MCP externo

En Ajustes → MCP → Servidores MCP disponibles, configura cada servicio y pulsa Iniciar. ZeroChat prepara sus dependencias declaradas. Para detenerlo, pulsa Detener.

Servicio incluidoUso y requisitos
ejemploPlantilla para servicios propios; no descarga dependencias.
composioAplicaciones remotas mediante mcp-remote y OAuth; Node.js 18+ y npm.
playwrightAutomatización de navegador; Node.js 18+, npm y Chromium. Si browser_action está activa, ZeroChat pide confirmación antes de sustituirla.
memoryMemoria y grafos de conocimiento; Node.js 18+ y npm.

Instalar Node.js en Windows

Abre PowerShell e instala la versión LTS con winget, incluido en Windows 10 y 11:

winget install OpenJS.NodeJS.LTS

También puedes descargar el instalador LTS (.msi) desde nodejs.org y aceptar las opciones por defecto, que añaden Node.js y npm al PATH.

  1. Cierra PowerShell y abre una ventana nueva para que se cargue el PATH actualizado.
  2. Comprueba la instalación con node --version y npm.cmd --version.
  3. Reinicia ZeroChat desde esa ventana nueva: el servidor solo detecta Node.js y npm si estaban en el PATH al arrancar.

Si npm --version falla con un error de directiva de ejecución de scripts, usa npm.cmd. ZeroChat no se ve afectado por esa directiva.

Arranque y OAuth

El botón muestra Iniciando y queda deshabilitado. Si el arranque supera 15 segundos, ZeroChat consulta el estado y espera en intervalos de 15 segundos: hasta 20 minutos mientras instala dependencias (por ejemplo, Playwright y su navegador) o espera la autorización OAuth, y hasta diez intervalos más mientras inicia. La instalación y la espera de OAuth no se consideran fallos al vencer el primer timeout; cuando el servicio está activo, el panel se actualiza automáticamente. El botón indica el número de intento.

Si el servicio necesita OAuth, la tarjeta muestra el aviso Se requiere autorización con el botón Autorizar en el navegador. ZeroChat intenta abrir la pestaña de autorización; si el navegador la bloquea, pulsa el botón. Al abrirse desde la propia web, funciona también en Android y Termux. Si se agota la espera, el servicio puede seguir arrancando; recarga la página para comprobar el resultado.

Los servicios no se reinician automáticamente en el siguiente arranque de ZeroChat. Si había alguno habilitado, un aviso lo recuerda al conectar; inícialos desde este panel cuando los necesites.

Si falla la instalación

Lee el error de la tarjeta. Comprueba node --version, npm --version, la conexión a la red y el espacio libre; después vuelve a intentarlo. No necesitas reinstalar ZeroChat. En Windows, consulta Instalar Node.js en Windows.

4. Revisa los permisos

En Ajustes → Permisos, elige la política global y revisa las autorizaciones guardadas. En el panel MCP puedes elegir Preguntar, Permitir o Denegar para cada herramienta.

  • Pedir autorización: pregunta cuando las reglas existentes no resuelven la llamada.
  • Confiar en el espacio de trabajo: además de las reglas de directorio, permite archivos con rutas relativas dentro del proyecto y comandos simples: sin encadenar (;, &&, $()), sin redirigir a archivos, sin rutas absolutas, ~, variables ni .., y con tuberías solo hacia filtros como head, grep o wc. El resto pide confirmación. No es un aislamiento: un comando simple como python3 script.py actúa con tus permisos.
  • Todo autorizado: ejecuta sin confirmación, salvo bloqueos explícitos que tengan prioridad.

Las decisiones pueden aplicarse a una llamada, a la sesión del backend o de forma permanente. Las herramientas externas se llaman <servicio>_<herramienta>: confiar en composio autoriza sus herramientas, no las de otros servicios. Permitir una herramienta no autoriza todo el servicio.

Directorios permitidos: una regla por línea con R: (lectura), W: (escritura) o RW: (ambas). Usa * para un segmento y ** para subdirectorios. Una lista vacía incorpora una regla de lectura para el directorio de arranque. Las rutas con ~ o variables no se resuelven en el navegador y siempre piden confirmación: usa rutas absolutas. Los comandos también tienen reglas de prefijos y comprobaciones adicionales.

Permitir siempre un comando: autoriza solo ese programa, sin encadenamiento, tuberías ni redirecciones a archivos. Un cd <carpeta> && inicial se admite si la carpeta está cubierta por una regla de directorio, igual que el directorio de trabajo del comando. Autorizar un programa confía en todas sus opciones: git puede ejecutar otros comandos mediante su configuración o alias.

Estas reglas no son un aislamiento del sistema operativo. Los comandos y servicios autorizados actúan con los permisos del proceso local. Detener una llamada no revierte sus cambios.

5. Añade tu propio servicio

Crea una carpeta nueva dentro de ~/zerochat/services/ con nombre e id únicos. Usa ejemplo como plantilla: service.json es obligatorio; añade installer.json solo para paquetes npm. El README.md de la plantilla describe los campos, incluido el enlace opcional help.

Puedes pedir al agente que cree la definición con uno de estos prompts. Sustituye los marcadores. El agente prepara los archivos; tú introduces las credenciales y arrancas el servicio.

6. Introduce una API key

launch.env indica el objeto env dentro de launch en service.json; no es un archivo. El agente deja el marcador y tú introduces la clave real a mano en ese JSON.

  1. Detén el servicio si está activo. Abre el service.json de tu carpeta.
  2. Sustituye PASTE_API_KEY_HERE en launch.env por la clave real, usando el nombre de variable que exige el proveedor. No la pegues en el chat.
  3. Guarda un JSON válido. En Linux o Termux limita el acceso con chmod 600 /ruta/absoluta/zerochat/services/mi-servicio/service.json.
  4. Inicia el servicio desde Ajustes → MCP.

La clave queda en texto plano: no compartas ni subas este archivo al repositorio. Borrar ~/zerochat/ también elimina los servicios y sus credenciales; conserva una copia privada si la necesitas.

Ejemplo para un servicio local

Dentro de launch, utiliza el nombre de variable indicado por el MCP:

"env": {
  "SERVICE_API_KEY": "PASTE_API_KEY_HERE"
}

No necesitas export, un archivo .env ni otro JSON de credenciales. Escribe el valor real en launch.env; las referencias a variables de entorno en ese campo quedan como texto literal. ZeroChat sustituye rutas de servicio/intérpretes y referencias ${option:...}.

Ejemplo para un servicio remoto con cabecera Bearer

Adapta los argumentos del puente y conserva el aislamiento existente de HOME y USERPROFILE:

"args": [
  "${serviceDir}/node_modules/mcp-remote/dist/proxy.js",
  "https://mcp.example.com/mcp",
  "--header",
  "Authorization: Bearer ${REMOTE_API_KEY}"
],
"env": {
  "HOME": "${serviceDir}",
  "USERPROFILE": "${serviceDir}",
  "REMOTE_API_KEY": "PASTE_API_KEY_HERE"
}

mcp-remote resuelve ${REMOTE_API_KEY} en la cabecera. Usa la cabecera y el formato que exija el proveedor. remote.authentication es descriptivo; no configura la autenticación. Consulta la documentación de cabeceras del puente.
