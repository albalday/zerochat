Protocolo MCP (Model Context Protocol)

Servidor local, servicios MCP y alcance de los permisos.

Las herramientas locales tienen nombres como read_file o execute_command. Las externas usan <servicio>_<herramienta>. Los permisos se asocian al nombre completo; autorizar una herramienta no autoriza otra del mismo nombre en un servicio distinto.

1. Qué es MCP

MCP permite descubrir e invocar herramientas de otros procesos. En ZeroChat, el servidor local conecta la interfaz del navegador con herramientas del equipo y servicios externos gestionados.

Para este flujo, inicia zerochat o python3 zerochat.py. El servidor escucha en la interfaz local y abre la web con el token de sesión. Sin el servidor puedes seguir usando el chat y las herramientas de navegador disponibles.

2. Conexión y estado

Abre Ajustes → MCP para ver el estado y las herramientas descubiertas. No hay un formulario de conexión manual: utiliza el enlace abierto por el comando de arranque.

Si aparece desconectado, comprueba que el proceso siga en ejecución, vuelve a abrir su enlace y revisa los permisos de acceso a la red local del navegador. No compartas el enlace de arranque con su token.

3. Servidor local

Puedes instalar el ejecutable desde PyPI o descargar el script. Fuera del repositorio de desarrollo, ambos abren la interfaz de GitHub Pages y guardan su estado en ~/zerochat/.

# PyPI
pip install zerochat && zerochat

# Descarga directa
curl -sL https://albalday.github.io/zerochat/zerochat.py -o zerochat.py && python3 zerochat.py

El arranque prepara config/, services/ y .venv/ para los MCP Python. Revisa los avisos si falla la creación del entorno antes de iniciar servicios. El ejecutable principal sigue usando el intérprete con el que lo arrancaste.

  • list_directory: lista directorios; admite recorrido recursivo limitado.
  • read_file: lee texto con rangos y límites de tamaño.
  • write_file: crea o sobrescribe archivos.
  • edit_file: sustituye un fragmento que debe coincidir una sola vez; también admite modos de compatibilidad.
  • search_files: busca texto o expresiones regulares en archivos.
  • bash y execute_command: ejecutan comandos; la sesión shell puede conservar directorio y variables entre llamadas.
  • get_diagnostics: recoge comprobaciones de sintaxis disponibles; no sustituye las pruebas del proyecto.
  • browser_action: automatiza Chromium cuando están instalados sus requisitos.

Las peticiones MCP usan el token en cabeceras. Las llamadas a herramientas requieren además una autorización firmada de corta duración y un solo uso. El token local se conserva por día; la clave de firma se renueva al reiniciar el proceso.

Si la terminal muestra [i] información, pulsa i para consultar avisos como una actualización disponible.

4. Permisos

En Ajustes → Permisos puedes elegir la política global, revisar reglas recordadas y servidores confiables. El panel MCP permite habilitar herramientas y elegir Preguntar, Permitir o Denegar.

  • Pedir autorización: pregunta cuando las reglas existentes no resuelven la llamada.
  • Confiar en el espacio de trabajo: permite operaciones que coinciden con las reglas del directorio; no crea una máquina aislada.
  • Todo autorizado: permite ejecutar sin confirmación, salvo bloqueos explícitos que tengan prioridad.

El panel de Permisos utiliza secciones abiertas con separadores discretos y fondos suaves para las políticas y autorizaciones guardadas. Los títulos y detalles se adaptan al ancho disponible.

Las decisiones pueden aplicarse a una llamada, a la sesión del backend o de forma permanente. Confiar en un servidor autoriza un conjunto más amplio que una sola herramienta. Revisa ese alcance antes de recordarlo.

En los diálogos de autorización, cada herramienta MCP externa identifica su servicio de origen. Confiar en composio autoriza sus herramientas, sin autorizar las de otros servicios externos. La autorización individual se aplica únicamente a la herramienta seleccionada.

Directorios permitidos admite reglas por línea: R: para leer, W: para escribir y RW: para ambos, con * para un segmento y ** para subdirectorios. Una lista vacía incorpora una regla de lectura para el directorio de arranque. Los comandos tienen reglas de prefijos y comprobaciones adicionales.

Estos permisos no son un contenedor del sistema operativo. Un comando o servicio autorizado actúa con los permisos del proceso local y puede producir cambios fuera del objetivo previsto. Revisa argumentos y conserva copias o control de versiones; detener una llamada no revierte lo realizado.

5. Servicios MCP externos

En Ajustes → MCP → Servidores MCP disponibles puedes configurar, iniciar o detener cada servicio. Al pulsar Iniciar, ZeroChat instala automáticamente el paquete npm y sus dependencias en el directorio propio del servicio. Si no puede preparar un requisito, la tarjeta muestra el error y enlaza a esta sección. Los servicios habilitados en una sesión anterior no se reinician automáticamente; al conectar, ZeroChat muestra un aviso para que los inicies desde esta sección después de comprobar las actualizaciones de la web. Si aceptas recargar para actualizar, el aviso se muestra en el siguiente arranque.

El panel separa las secciones con títulos y líneas discretas, y resalta cada servidor con un fondo suave. En móvil, el estado de conexión y los contadores se distribuyen según el ancho disponible, y las acciones aparecen debajo de la descripción.

  • ejemplo: plantilla incluida para crear servicios MCP gestionados; no descarga dependencias. Su tarjeta enlaza a esta guía.
  • composio: conexión remota mediante mcp-remote al endpoint de Composio Connect. Requiere Node.js 18+ y npm; ZeroChat instala el puente en su directorio propio. Al usar una aplicación como Gmail, Composio presenta su autorización OAuth en el navegador. Las credenciales y el estado OAuth del puente quedan aislados dentro del directorio del servicio.
  • playwright: requiere Node.js 18+ y npm. ZeroChat instala @playwright/mcp y Chromium. La descarga de Chromium necesita red y espacio en disco. Si browser_action está activa, ZeroChat pide confirmación antes de desactivarla y sustituirla por las herramientas completas de Playwright.
  • memory: requiere Node.js 18+ y npm. ZeroChat instala @modelcontextprotocol/server-memory y sus dependencias.

Si falla una instalación, comprueba la versión indicada de Node.js con node --version, que npm --version funcione, la conexión a npm y el espacio libre. Corrige el requisito y vuelve a pulsar Iniciar; no es necesario reinstalar ZeroChat.

Al pulsar Iniciar, el botón muestra Iniciando y queda deshabilitado. Si el arranque supera 15 segundos, ZeroChat consulta el estado y espera hasta diez intervalos adicionales de 15 segundos mientras siga en iniciando, mostrando el número de intento. Completa la autorización OAuth en el navegador. Si se agota la espera, el servicio puede seguir arrancando: recarga la página para comprobar el resultado en el panel MCP.

Los servicios se gestionan bajo ~/zerochat/services/. Borrar ~/zerochat/ elimina ese estado y sus dependencias, pero no el historial del navegador ni archivos modificados fuera de esa carpeta.

En Termux, ZeroChat prepara un puente xdg-open para que los MCP abran los enlaces de autorización con termux-open-url.

Al arrancar, ZeroChat restaura los archivos de configuración incluidos para ejemplo, composio, playwright y memory. Conserva sus dependencias instaladas y sus datos, además de las carpetas de servicios creadas por el usuario.

Crear un servicio MCP con un agente

Usa ~/zerochat/services/ejemplo/ como estructura de referencia. Cada servicio necesita service.json; añade installer.json solo cuando ZeroChat tenga que instalar un paquete npm. El campo opcional estándar help permite que el JSON defina un enlace visible en la tarjeta del servicio:

"help": {
  "url": "help/mcp.html#crear-mcp-con-agente",
  "label": { "es": "Guía del servicio", "en": "Service guide" }
}

La URL debe ser una ruta relativa de ZeroChat o una URL https: o http:.

Crear un MCP local (stdio)

Copia este prompt y sustituye <nombre-del-mcp>. El modelo crea la definición; tú introduces la clave y arrancas el servicio:

Quiero crear el MCP local <nombre-del-mcp> para ZeroChat.
Localiza el directorio personal del usuario y lee README.md,
service.json e installer.json.example de zerochat/services/ejemplo
usando sus rutas absolutas. Sigue las instrucciones del README.
Consulta la documentación oficial del MCP y crea una carpeta hermana
con nombre e id propios; no modifiques los servicios incluidos.
Si necesita una API key, deja PASTE_API_KEY_HERE en launch.env,
con el nombre de variable que exige el MCP. No me pidas la clave.
Indica la ruta absoluta del JSON y el campo que debo editar a mano.
No instales ni inicies el servicio; lo haré desde Ajustes → MCP.

Quiero crear el MCP remoto <nombre-del-mcp> para ZeroChat.

usando sus rutas absolutas. Sigue el README y toma Composio
como ejemplo de un puente mcp-remote gestionado por stdio.
Crea una carpeta hermana con nombre e id propios y textos bilingües.
Consulta la documentación oficial del MCP y del puente para adaptar
endpoint, transporte y autenticación. No copies sin verificar las
opciones específicas de OAuth o protocolo de Composio.
Conserva el aislamiento HOME y USERPROFILE en ${serviceDir}.

configura --header con la cabecera que exige el proveedor y una
referencia a esa variable; mcp-remote resolverá la referencia.
No me pidas la clave ni la escribas en los argumentos o en la URL.

Introducir y conservar una API key

  1. Crea una carpeta propia dentro de ~/zerochat/services/, con service.json y, si necesita npm, installer.json. Puedes pedirlo con los prompts anteriores o copiar la definición de un servicio existente, sin copiar sus dependencias ni credenciales OAuth.
  2. Si copias una definición, cambia el nombre de carpeta, el id del JSON y los textos visibles. El id debe ser único. Ajusta el endpoint y la autenticación según la documentación del proveedor; cambiar solo la clave no convierte OAuth en autenticación por API key.
  3. Abre el service.json de tu carpeta y sustituye PASTE_API_KEY_HERE por la clave real dentro de launch.env. Usa el nombre exacto de variable que espera el MCP. No pegues la clave en el chat.
  4. Guarda un JSON válido, conservando el resto de launch. En Linux y Termux limita el acceso al archivo con chmod 600 /ruta/absoluta/zerochat/services/mi-servicio/service.json. La clave queda en texto plano: no compartas ese archivo ni lo subas al repositorio.
  5. Abre Ajustes → MCP y pulsa Iniciar. Si la carpeta nueva no aparece, reinicia ZeroChat y vuelve a conectar. Para cambiar la clave de un servicio activo, detén el servicio, edita el JSON y vuelve a iniciarlo.

Ejemplo de un campo dentro de launch para un MCP local; reemplaza el nombre de variable por el que indique el proveedor:

"env": {
  "SERVICE_API_KEY": "PASTE_API_KEY_HERE"
}

No necesitas export, un archivo .env ni un JSON adicional de credenciales. ZeroChat pasa el valor escrito en launch.env al proceso MCP. ${SERVICE_API_KEY} dentro de ese campo sería texto literal: ZeroChat solo sustituye las rutas de servicio/intérpretes y las referencias ${option:...}.

Para un remoto que acepte Authorization: Bearer, adapta los argumentos del puente y añade la clave al env existente, conservando HOME y USERPROFILE:

"args": [
  "${serviceDir}/node_modules/mcp-remote/dist/proxy.js",
  "https://mcp.example.com/mcp",
  "--header",
  "Authorization: Bearer ${REMOTE_API_KEY}"
],
"env": {
  "HOME": "${serviceDir}",
  "USERPROFILE": "${serviceDir}",
  "REMOTE_API_KEY": "PASTE_API_KEY_HERE"
}

En este caso mcp-remote, no ZeroChat, resuelve ${REMOTE_API_KEY} en la cabecera. Si el proveedor exige otra cabecera, como X-API-Key, usa esa cabecera y su formato. El campo remote.authentication describe el servicio para la interfaz; no configura la autenticación. Consulta la documentación oficial de cabeceras del puente.

Los archivos de tu carpeta propia se conservan al reiniciar y actualizar ZeroChat. No edites los JSON de las carpetas distribuidas (ejemplo, composio, playwright y memory): se restauran en cada arranque. Borrar ~/zerochat/ también elimina tus servicios y sus claves; conserva una copia privada si la necesitas.

Los parches de una misma serie, como 8.0.x, llegan con la web. Un cambio de major.minor puede requerir actualizar el backend. Sigue el aviso correspondiente a PyPI o a la descarga directa; la actualización no es automática.
