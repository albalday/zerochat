Perfiles y Proveedores de IA

Configurar conexiones, modelos, claves y copias de perfiles.

1. Gestión de perfiles

Un perfil reúne proveedor, URL, clave API, modelo y ajustes de generación y herramientas. Pulsa el nombre del perfil en la cabecera para seleccionarlo, crearlo, editarlo o borrarlo. Puedes cambiar de perfil entre mensajes; el historial existente pasa al nuevo proveedor en los siguientes envíos.

El editor incluye temperatura, instrucciones, razonamiento y límite de turnos del agente. Con Google Gemini la temperatura aparece desactivada y se usa la del modelo, porque Google retira los parámetros de muestreo personalizados. Guardar aplica los cambios; Bloquear cambios evita la edición habitual del perfil, pero no es un control de acceso al equipo.

Exportar descarga un HTML con los perfiles editables cifrados. Ábrelo para iniciar su importación en ZeroChat y confirma los cambios: se añaden perfiles nuevos y se actualizan los del mismo identificador. Espejo se conserva.

En Configuración → Cifrado puedes establecer una contraseña propia o volver a la predeterminada. La clave integrada de la aplicación es conocida; el cifrado predeterminado no protege secretos frente a quien accede al almacenamiento o a la copia. Con contraseña propia se conserva material de desbloqueo en el navegador durante 24 horas. Trata las copias como archivos sensibles y conserva la contraseña: no hay recuperación de claves olvidadas.

La compatibilidad de chat no implica que todos los modelos admitan imágenes, herramientas o razonamiento. También intervienen CORS, permisos de red local y restricciones del navegador.

3. Consultar el servidor con Query

  1. Elige el tipo de API y completa URL y clave cuando corresponda.
  2. Pulsa Query para consultar modelos y datos disponibles.
  3. Selecciona el modelo, revisa los ajustes y guarda.

Los perfiles de red requieren una consulta satisfactoria antes de guardar. Las capacidades pueden proceder de metadatos o de inferencias a partir del modelo: una consulta correcta no garantiza que todas las operaciones posteriores funcionen.

En WebLLM puedes guardar un modelo ya descargado sin repetir Query. Para preparar otro, abre el catálogo y completa su descarga.

4. Inspección del perfil

La lupa del selector consulta el modelo configurado y muestra su disponibilidad, contexto y diagnóstico de capacidades. Si falla, comprueba URL, clave, servicio en ejecución y acceso desde el navegador.

El diagnóstico ayuda a localizar problemas, pero no certifica la compatibilidad de cada función. Prueba una conversación sencilla antes de añadir imágenes o herramientas.

5. Ollama y CORS

Si el navegador bloquea el acceso por CORS, permite el origen desde el que abres ZeroChat en la configuración de Ollama y reinicia su servicio. Para GitHub Pages, el origen es https://albalday.github.io.

# Linux / macOS
OLLAMA_ORIGINS="https://albalday.github.io" ollama serve

# Windows PowerShell
$env:OLLAMA_ORIGINS="https://albalday.github.io"
ollama serve

Si Ollama ya se ejecuta como servicio, modifica el entorno de ese servicio en lugar de iniciar una segunda instancia. Para la interfaz local añade su origen exacto. Consulta la documentación de Ollama. CORS no sustituye autenticación ni resuelve todos los bloqueos de red local del navegador.

6. Perfil Espejo

Espejo es un perfil de prueba de solo lectura que muestra el mensaje y la estructura de la petición normalizada, sin llamar a un modelo. Sirve para revisar la interfaz y el formato del envío.

No genera respuestas de IA ni valida un proveedor externo. Que Espejo funcione no prueba que la red o las credenciales estén bien configuradas.
