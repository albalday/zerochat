Infrastructure and data

How features are divided between the browser and the local server.

Usage levels

ZeroChat runs the same agentic engine across five progressive levels: start in the browser with zero installation and add the local server or unattended execution only when you need them.

LevelWhat you needWhat it enables
1. Simple chat (frontend only)Browser (or PWA)Chat, profiles, attachments, in-browser RAG, sandboxed JavaScript, web search/reading and WebLLM (WebGPU). No access to local files.
2. Chat with local backendzerochat (Python)Per-project controlled access to files and commands (RWX rules), project-mode development, MCP services, model browser and SQLite sync.
3. CLI executionzerochat + Node.js ≥ 22.13Unattended shell or cron requests via --prompt and --conversation without opening a browser, returning answers on stdout.
4. Server background runszerochat + Node.js ≥ 22.13Turns launched from the UI as independent processes: close the browser and return later to inspect progress or answer a needs_input.
5. Agent orchestrationszerochat + Node.js ≥ 22.13Unattended agents via --run-file, controller agents launching and monitoring workers (launch_agent, check_agents) and human supervision in the Agents tab.

If supported, you can install the web app as a PWA. Cached resources do not guarantee every feature works offline.

Tested environments: Linux (x86_64 and ARM), Windows 10/11 (PowerShell and py -m zerochat launcher), and Android (Termux with the python package). Playwright cannot currently be used on Termux, so browser_action and Playwright MCP are not available.
Browser compatibility: ZeroChat is not compatible with Safari due to Private Network Access limitations and web storage policies. On macOS it should work with Firefox or Chromium-based browsers, but it has not been tested.

Where data is stored

In the browser

Without the server, conversations, profiles, attachments and RAG live in browser storage (scoped to the web origin and browser profile). When connected to the local server, profiles and conversations sync through SQLite so you can continue from another browser or device. Export copies before clearing data.

Conversations are not encrypted as a vault. See Profiles for how API keys are stored and its limits.

On your computer, with the local server

~/zerochat/
├── storage/     SQLite database (conversations, profiles, permissions, secrets and runs)
├── config/      Daily session token
├── general/     Default folder for chats without a project
├── services/    Managed MCP services and their dependencies
├── cache/       Node.js runner module cache
└── .venv/       Isolated environment for Python MCP services

PyPI and the downloaded script share the same folder. Deleting it resets all backend state (including the database and managed services), without touching the executable, browser copies or your project files.

Connections and privacy

The published interface is GitHub Pages. The local server listens at 127.0.0.1:6388 by default and opens an authenticated link. Do not share the startup URL while it contains the token; the interface removes it and stores it in a cookie. Without that link (another computer, an SSH tunnel or a reverse proxy), the connection is set up in the Connection panel (the plug icon next to the settings wheel in the sidebar) and the page asks for the user name and password of the account running the server to get the daily token.

Remote providers receive messages, attachments and tool results included in their requests. Web tools do not use public proxies or intermediaries. Models and dependencies also require downloads.

Third-party libraries (Orama for search; mammoth and fflate for office documents) ship with the web app itself at pinned versions, with no CDN. The document libraries are downloaded from the same site the first time they are used and cached for offline work. Their licenses are listed in THIRD_PARTY_NOTICES.md.

WebLLM runs inference locally; network tools still send data. Local history does not make all operations private. The debug panel shows requests; their context may differ from visible history because of token limits or RAG selection.

Updates

Web updates arrive from GitHub Pages. Patches in the same series, such as 9.1.x, are compatible with backend 9.1 and do not require reinstalling it. When a new web version is ready, ZeroChat offers Reload now or Later; reloading applies it without losing saved history.

A new major.minor series may require a backend update. Follow the terminal notice for your installation method; the executable does not update automatically. Press i when the terminal offers information.

Local development

Inside the repository, python3 zerochat.py serves http://127.0.0.1:6388/zerochat.html. Its browser storage is separate from GitHub Pages. The interface loads js/ and css/; copying the HTML alone is not enough.

python3 zerochat.py --test checks local tools. For the project test suite, see tests/README.md in the repository.
