Architecture & Portability

How features are divided between the browser and the local server.

1. Web application and local backend

The interface is served as static files: zerochat.html loads modules from js/ and css/. It is not one self-contained HTML file. The browser runs the interface, stores data and sends requests to the selected provider.

The optional backend is the PyPI zerochat executable or the zerochat.py script. It adds computer tools and MCP service management. It is not required for chat with a provider accessible from the browser.

2. Launch modes

A. Web

Open the GitHub Pages interface over HTTPS. It includes profiles, chat, attachments, RAG, browser tools and WebLLM if the device supports WebGPU. Remote APIs require network access, credentials where applicable and browser access permissions.

PWA installation depends on the browser and uses its own options. ZeroChat has no install button or prompt. The Service Worker can reuse cached resources without guaranteeing every feature works offline.

B. Local backend

Adds file reading and writing, search, commands, diagnostics, browser automation and MCP services. It requires Python and each tool's own dependencies. Availability must be checked on the actual operating system.

3. Published web app and local development

Outside the repository, the executable opens GitHub Pages and listens at 127.0.0.1:6388 by default. The interface receives the startup token, removes it from the address and stores it in a cookie for the web origin. Do not share that URL before the token is removed.

Inside the repository, python3 zerochat.py detects development files and serves http://127.0.0.1:6388/zerochat.html. This origin has separate storage from GitHub Pages.

python3 zerochat.py --test runs a tool self-check. npm test runs the project suite and npm run test:browser runs browser tests. A self-check does not validate every provider or platform.

4. Distribution and updates

pip install zerochat installs the Python executable; direct download provides zerochat.py. The interface loads separately from GitHub Pages. Both modes prepare this local state:

~/zerochat/
├── .venv/       Python MCP dependencies
├── config/      Token and configuration
└── services/    MCP services

Deleting this folder removes that state, not the installed executable, browser history or files changed outside it.

Compatibility is identified by major.minor: for example, web interface 8.0.x corresponds to backend 8.0. Web patches do not require reinstalling it. For a new series, the notice gives the PyPI update command with its interpreter or the script download. Updates are not automatic.

5. Storage and privacy

What is stored

IndexedDB holds conversations, profiles, attachments and RAG. Other preferences and unlocking material use browser storage; models use cache. Data belongs to the origin, browser and profile used. There is no automatic sync or guarantee of retention if the browser removes it.

Conversations are not encrypted as a vault. API keys have local encryption with limitations explained in Profiles. Export copies of what you need before clearing data.

What leaves the computer

Remote providers receive messages, attachments and tool results included in their requests. Web searches and page retrieval may pass through external services such as Jina Reader or AllOrigins; dependencies and models may also download from external servers.

WebLLM performs local inference, but network tools still communicate externally. Review provider and tools before sending sensitive content. Keeping history locally does not mean absolute privacy.

6. Application state

ChatState coordinates configuration, sessions, messages, generation, agent, telemetry, interface and permissions. Modules use domain mutators to keep changes synchronized.

This is an internal architecture decision. It does not add cross-device sync or make a browser session an isolated environment for each backend tool.

7. Shared conversation rules

Turn management, message components and error presentation are shared between new and restored conversations. Saved tools retain their results in history.

Visible history and context sent to the provider can differ because of token limits, provider adaptation or RAG passage selection. Use the debug panel to inspect a particular request.
