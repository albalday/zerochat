Review 3: Comparison

ZeroChat versus Open WebUI, LM Studio, the llama.cpp interface and Jan, now that all of them have tools. Updated on 14 November 2026.

Validity and method: the ZeroChat data was checked in its code (version 10.16.0, commit 865cbba). The rest comes from each product's official public documentation, consulted on 13 November 2026. What that documentation does not state is marked "not stated", not "no". The other products were neither installed nor measured.

1. What is compared

ZeroChat sits in front of a model server that is already running. It is compared with the interfaces that occupy the same place: Open WebUI, LM Studio, the interface bundled with llama-server and Jan.

The ground has moved in two directions since the previous review. The others have gained tools: the llama.cpp interface now accepts MCP servers and its own read and execution tools, experimentally, and Jan offers a terminal agent. ZeroChat, for its part, has moved history, permissions and background execution to the server. The comparison is no longer "who has tools" but how they are governed and where the work lives.

3. Analysis

Versus the llama.cpp interface

It is no longer just a test chat: it accepts MCP and read and execution tools, although its own documentation marks them as experimental and warns that they must not be enabled in untrusted environments. No per-call permission system is stated. ZeroChat connects to the same llama-server and adds what is missing there: rules, per-project history and background execution. For someone who only wants the model to read a file now and then, the bundled interface is starting to be enough.

Versus LM Studio

Its tool confirmation is good and simple: see the call, edit the arguments and allow once or always. ZeroChat is finer (per-argument patterns, scopes, directories) and also harder to understand. LM Studio wins on ease of installation and model management; ZeroChat on engine independence and on taking the whole environment to another device.

Versus Open WebUI

It is the reference for shared deployments: users, roles, vector RAG and centrally administered tools. Its native MCP is HTTP only and is registered by the administrator. ZeroChat covers the opposite case: one person, their machine and their folders, with no database to administer. With history in SQLite the architectural distance is smaller than before, but the difference in purpose remains.

Versus Jan

It combines a desktop app, a local API and a terminal agent. Its tool control is all or nothing. ZeroChat offers more control and more transparency in exchange for more configuration.

What the matrix leaves out

For programming with a local model, the real alternative to ZeroChat is also the terminal agents, which were not compared here because they are not chat interfaces. Anyone weighing ZeroChat for that use should measure it against them on real tasks; that comparison is still pending.

4. ZeroChat differentiators for this use

  • Permissions at command and directory granularity, decided on the server and tested; this is what most separates it from the rest.
  • The work lives on the server: a task continues with the browser closed and resumes from the phone.
  • Engine independence: one client for vLLM, llama.cpp, LM Studio, SGLang or Ollama.
  • Projects: history, permissions and commands separated by folder.
  • A server with no dependencies: one Python file; it also runs on Android with Termux.
  • Editable interceptor for the exact JSON sent to the model.

Trade-offs: lexical-only RAG, one person per server and more concepts to learn than in any of the alternatives.

5. When to choose each

  • ZeroChat: one person working with an agent on a separately served local model, who wants precise control over what it can do on their machine and to follow the work from another device.
  • LM Studio: an application that downloads, runs and serves the model, with MCP tools confirmed by hand.
  • llama.cpp interface: quick checks and occasional tool use without installing anything else.
  • Open WebUI: several users, central administration or vector RAG.
  • Jan: simple personal desktop use, with MCP and no fine configuration.
