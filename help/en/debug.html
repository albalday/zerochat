Debugging, Logs & Interceptor

Inspecting requests, tool results and connection errors.

1. Debug panel

Open the panel using the terminal icon in the header. It shows application events and information about model and tool requests.

  • All: all recorded events.
  • Thinking: reasoning content exposed by the provider.
  • Tool: calls and results.
  • Network: recorded request information.
  • Raw: inputs and outputs without chat formatting.

This is not a full capture of browser traffic. Loading, CORS or network errors may also require the browser developer tools.

2. Reading and copying logs

The panel toolbar lets you copy logs and clear the console. The log automatically follows new entries; scrolling up pauses it, and it resumes when you return to the bottom, switch tabs or open the panel.

Logs may contain messages, documents, arguments and tool responses. Review and remove private information before sharing; filtering credentials does not anonymize all content.

3. Message interceptor

Enable Debug messages to inspect the prepared JSON before it is sent to the provider. You can edit and send it, send it while disabling the interceptor, or cancel with X.

Use it to check how messages, tools and parameters are packaged. An edit may invalidate the request or change what the model receives. Cancelling prevents that pending request but does not undo earlier requests or actions.

4. Raw view

Raw displays request, response and streaming information recorded by ZeroChat. Entries are limited to contain panel size, so it should not be treated as a complete audit archive.

When reporting a failure, record the provider, model, action and error, and share only the necessary log excerpt.
