Project and learning

Two learning tracks: building an AI client and learning to guide its development with agents.

ZeroChat is the developer’s personal self-learning project. Its goal is to understand chat client technology and agentic execution, and to experiment with Codex and Antigravity without ever editing code by hand. The human work is to define goals, discuss decisions with the model and check results; the agents implement the changes.

1. Learning chat client technology

The history traces a path from ChatCLI to a client with local knowledge and tools:

  • Chat and providers: SSE streaming, reasoning, vision and API adaptation. The provider architecture was separated in August 2026 (9bd4b1d).
  • Data and documents: IndexedDB persistence, PDF extraction and retrieval-augmented generation (RAG). After exploring file storage, the engine was unified around Orama and ZeroChatDB in September (481c9c6).
  • Agentic execution: tool loops, JavaScript isolated in Web Workers, MCP and permissions. This evolved into a local Python server with development tools and Playwright (219ed4a).
  • Inference and context: caching, token limits and checkpoints for long conversations; later, models running inside the browser with WebLLM and WebGPU (6bd4b31, e20a70c).

2. Learning to guide coding agents

As the infrastructure grows—browser, storage, providers, MCP server and bundle—learning also means keeping control of the whole system:

  • Plan before executing: define scope, stages and acceptance criteria. Git preserves the WebLLM plan before implementation and the design for splitting app.js before module extraction (e122f9f, b404c4a).
  • Turn decisions into rules: document architecture, contracts and Git workflow to guide the agent. The rules evolved towards AGENTS.md, centralized state in ChatState and separate responsibilities (cb06bc4, 66a1967).
  • Discuss and simplify with the model: question proposals, reuse modules and remove unnecessary complexity. The history records the unification of the agent runtime and the removal of obsolete code (3d2a7e5, 02a7729).
  • Verify each step: unit and browser tests, security audits and bundle validation. Maintaining tests is part of the learning: UI checks were introduced and duplicates were later removed (aae43d2, de0ffd5).

The plan is to keep repeating this cycle: choose a capability, agree on a simple design, assign scoped changes, review tests and document what was learned.

Based on Git history through September 14, 2026. The commitment to work with Codex and Antigravity without manual coding was documented in 65746ba. These identifiers locate the milestones in the repository.
