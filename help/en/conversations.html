Conversations, History & Branching

Local history, branches and conversation backups.

1. Sidebar and history

The sidebar lets you create, search, open, export and delete conversations (on mobile it fills the whole screen). Each conversation belongs to the project where it was created; chats created offline or in ~/zerochat/general go to general, where project mode is not used. A new conversation keeps the selected profile, and switching conversations does not change the tab's active profile.

  • Views and search: the selector below the search box switches between the current project, general and All projects (collapsed on entry so it works as a project picker). Each group shows 50 conversations with a Show more button. The folder icon in the header opens a read-only browser for the active project's files in a new tab (text files open in a tab; binary files or those over 2 MB download, up to 100 MB).
  • Statuses and pending tasks: each unfinished server run shows a status icon (clock while running, question mark on needs_input, warning on error, pause on limit). When any conversation in the active history is waiting for your reply or approval, or ended with an error, Pending tasks appears in the selector (across all projects, not bulk-deletable). An error stays pending until you relaunch or delete its conversation.
  • Attention notice: while any conversation in any project is waiting for your reply or has failed, a notice above the message box shows how many there are among agents and chats, and the tab title carries their number, with a dot on the icon (red if any failed). If a new one arrives while the tab is in the background, the title flashes until you come back. The notice has no links: the details are in Pending tasks. It only works while ZeroChat is open and connected to the local server.
  • Agents history and supervision mode: agent conversations (--run-file with agent) live separately behind the Chats / Agents switch (a dot on the inactive tab signals a pending reply). They are listed by date under their agent identifier (<name> or <set>.<name>) (title on hover), cannot be renamed and are searchable by agent ID. Opening one enters supervision mode (read only) with a notice above the composer and without changing the tab's project or profile: you can answer a needs_input (resuming with its stored launch), cancel it, export it or branch into a normal chat.
  • Deletion and project switching: the delete-history button removes, after confirmation, only what is shown by the selector and active tab (chats or agents, never both; disabled when empty or in pending tasks). Deleting the open conversation opens another from the same history and project, or a new chat, without switching projects. Opening a chat from another project asks before moving the server to its folder; if the folder no longer exists, the chat stays readable with local tools and server runs disabled.
  • Server sync: when connected, conversations are saved to both IndexedDB and SQLite (~/zerochat/storage/zerochat.db) after every tool step. Connecting fetches headers right away and each conversation downloads its messages the first time you open it (offline, a cached local copy opens if present, otherwise a warning is shown). Offline changes upload on connect with most-recent-wins; offline deletions reappear if the server still holds them.

While a response is being generated, the view follows the end of the conversation; scrolling up pauses auto-scroll and shows a down-arrow button above the composer to jump back to the end.

2. Conversation branches

The branch button on a response creates another conversation departing from that point. The original retains all its messages and remains intact in history. You can switch between both from the sidebar and explore different hypotheses, questions, or profiles.

When branching a conversation with accumulated history, ZeroChat offers the option to summarize earlier context via a synthesis checkpoint. This consolidates past turns, tools, and decisions into a streamlined block, launching the new branch with a clean context window (saving tokens and latency) while preserving the starting response. If you prefer to copy all verbatim messages, simply uncheck the summary option. While the summary is being generated you cannot send messages or switch conversations; the stop button cancels it without creating the branch. If summarization fails, ZeroChat offers to branch with the full history. The summary appears collapsed at the top of the branch.

RAG branches are document collections and are managed separately.

3. Exporting conversations

  • JSON: an importable conversation copy, with messages and associated data included by the exporter.
  • Markdown: text to read or edit outside ZeroChat.
  • HTML: the conversation as it looks in the chat, in a single file that opens in any browser; tool cards are expanded and it contains no scripts.
  • Print / PDF: opens a print view; the browser can save it as PDF.

A conversation export is not a full application backup: profiles have their own export, and RAG collections and downloaded models are not included. Review a file before sharing: it may contain messages, attachments and tool results.

4. Importing and keeping backups

Use Import conversation in the sidebar and select JSON exported by ZeroChat. The application validates its structure; it does not import PDF or Markdown as chat history. Import is blocked during generation.

Export conversations you want to keep before clearing browser data. Deleting a session or the entire history requires confirmation and has no recovery bin. Deleting ~/zerochat/ resets the server SQLite storage, while preserving the browser IndexedDB copy.
