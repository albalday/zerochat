Review 1: Infrastructure and rules

Which AGENTS.md rule is protected by a test, and which depends only on someone reading it? Updated on 24 October 2026.

Scope and method

Review of version 9.11.0 on the dev branch (commit 170ee03), written from scratch against the current code. Since the previous review (9.2.3, commit 924aef6) there are 238 commits and 39 closed milestones (M5 to M43). It follows the docs/audits/AuditFull.md procedure.

The criterion is the 9.0.0 lesson: a rule only counts as met if a test fails when it is broken. Each statement shows where it comes from:

  • [test] an automated test protects it;
  • [cmd] a reproducible command checks it today, but nothing stops it from breaking;
  • [reading] code review, with no test or command;
  • [no test] a written rule that no test watches.

3. Local server security

  • Mandatory daily token on every request, in headers only. It expires at the day change even with the server running: the old one gets a 401 and a new one is generated. [test] test_local_server.js, py/test_token.py
  • Sign-in with the system account: without a token only sign-in is served, with a body of at most 4096 bytes. The password is checked with PAM (Linux and macOS) or LogonUserW (Windows) and never stored. After 5 failures in a row, attempts are rejected for 15 minutes without checking them. [test] py/test_login.py, test_local_server.js
  • No trust in the reverse proxy: the header the proxy routes by grants no access; behind it the token and sign-in are still required. [test] test_local_server.js and browser_connection.test.js
  • POST-only API over JSON-RPC, with CORS origins from a closed list; GET only serves the interface in development. [test] test_local_server.js
  • Each tool call signed with HMAC, a single-use nonce and a 60 s window that tolerates ±30 s of clock skew. [test] test_local_server.js
  • Bounded HTTP body of 1 MiB, except the --prompt --export export (64 MB). [test] test_local_server.js
  • Loopback listening by default, with a warning for any other host. [test] py/test_network.py
  • Server web transport with SSRF protection on the requested URL and on every redirect, and a bounded body. [test] py/test_network.py
  • Bounded commands: timeout, termination of the process group and cleanup of orphans from earlier sessions; on Windows, a Job Object. [test] py/test_run_command.py (the Job Object test only runs on Windows)
  • JavaScript sandbox in an opaque-origin iframe without network; the help warns that it is not a security barrier. [test] browser_sandbox_security.test.js
  • Tool permissions: ask, workspace_trust and allow_all policies, directory rules and traversal checks. [test] test_tool_security.js

4. Accepted risks

RiskSituation
Shared origin albalday.github.ioOther pages on the same origin could read the session cookie, localStorage and IndexedDB. Accepted while the origin only publishes the project's own pages.
Proxy key unencrypted in the browserStored in the local configuration (M42-D17): it only opens the proxy door, and the server still requires the daily token and sign-in. It is only sent to the configured URL.
System account lockoutIf the computer locks accounts after failed attempts (for example, pam_faillock) with a limit below 5, failures from the web could lock the account. The help explains how to avoid it.
Non-local --hostExposes command execution to the network without encryption; startup warns. For remote access, the SSH tunnel and the HTTPS reverse proxy are documented.
WebLLM from a CDNThe engine is imported from cdn.jsdelivr.net when this provider is used.
Web toolsDuckDuckGo search and page reading go through the local server or, without it, through Jina Reader.
Remote providersWith a cloud API, messages go to the configured provider; with a local LLM they do not.

Resolved in this version: a browser startup test assumed no real zerochat was listening on 127.0.0.1:6388; with one running, its 401 opened the sign-in dialog. The test now blocks that address.

6. Verdict

Solid infrastructure, with the network surface redesigned without losing protection. Since 9.2.3 the local server has moved to a POST-only transport, a daily token that expires while running, sign-in with the system account and remote access by tunnel or reverse proxy; each of those changes arrived with its tests. The suite is smaller and faster than in 9.2.3 and covers more features. What remains is Windows coverage (F-01), which today is only tested by hand.
