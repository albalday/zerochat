Review 1: Infrastructure and rules

Which AGENTS.md rules are protected by a test, and which depend only on someone reading them? Updated on 13 October 2026 with the closure of the findings.

Scope and method

Review of version 9.1.0 as prepared on the dev branch (commit a0393c3, before the version bump). It does not update the 8.12.4 audit: it starts from scratch, following docs/audits/AuditFull.md.

The criterion comes from the 9.0.0 lesson: a rule only counts as met if a test fails when it is broken. Each claim states its source:

  • [test] an automated test protects it;
  • [cmd] a reproducible command checks it today, but nothing stops it from breaking;
  • [reading] code review, with no test or command;
  • [no test] a written rule that no test watches.

3. Local server security

  • Session token required on every backend request. [test] test_local_server.js
  • Daily token in ~/zerochat/config/token.json with 0600 permissions and a 0700 directory. [test] test_backend_runtime.js (skipped on Windows)
  • Loopback by default, with a warning when listening on a non-loopback host. [test] test_backend_runtime.js
  • Every tool call signed with HMAC and a single-use nonce. [test] test_local_server.js
  • Bounded commands: 30 s by default, 600 s maximum, and the process group is terminated; on Windows, a Job Object. [test] test_backend_runtime.js; the Job Object test only runs on Windows and was skipped here
  • JavaScript sandbox: iframe with an opaque origin and CSP connect-src 'none'; it is not a security boundary, and the help says so. [test] test_sandbox.js and browser_sandbox_security.test.js
  • Tool permissions: ask, allow_all and workspace_trust policies, directory rules and blocks. [test] test_tool_security.js

All ten findings are closed; section 7 gives the closure details. Findings H-01 to H-04 from the 8.12.4 audit remain closed, and the two most relevant (empty catches and untranslated literals) are protected by tests.

6. Verdict

At review time the suite passed in full, but seven rules depended on an agent reading AGENTS.md, and R-01 showed that one was already broken. Closing R-01 to R-03 and R-08 before adding new functionality was recommended.

After closure, only two rules that cannot be checked statically remain without a test. Two of the new tests found breaches that reading had accepted: the MCP section listeners (R-02) and the injection in render_chart (R-08). This confirms the lesson: new rule, new test, same commit.
