7. Open Findings and Actionable Items

F1 · High — Authorization logic does not always compose constraints

In js/tool-security.js, evaluateAuthorization returns command_directory_rules_allow before evaluating saved command-specific constraints. Reproduction: with rule R:/tmp/zc-audit/** and command permission restricted to allowedPrefixes: ['ls'], executing cat /tmp/zc-audit/demo.txt is permitted. Isolated prefix evaluation prompts for approval; composite evaluation grants immediate execution without user intervention. AgentCore accepts this decision without further checks.

Furthermore, relative rule R:docs/** authorizes cat docs/demo.txt irrespective of current cwd. Real canonical filesystem paths and symlinks are unverified on the client. Additionally, invoking zmcp_list_directory without an explicit path bypasses directory rule evaluation and hits allow_all, despite the backend defaulting to ".".

Action: Normalize default parameters prior to evaluation; evaluate tool permissions, command prefixes, directory rules, and cwd jointly, ensuring explicit denials take precedence. To establish robust folder boundaries, validate canonical filesystem paths on the Python server. This requires clearly scoping UI authorization guarantees rather than attempting full OS sandboxing.

F2 · High — Unrecognized file edit mode triggers overwrite

In zerochat.py, validate_local_tool_arguments checks that mode is a string, but fails to validate allowed enum values. In edit_file, the fallback else branch performs a full file overwrite. Passing mode: 'invalid_mode' bypasses validation and replaces existing contents entirely. Tested on temporary files, where content changed unconditionally from ORIGINAL to CHANGED.

Action: Reject any mode other than write, append, and replace_chunk before modifying files or creating parent directories; validate required mode arguments and add HTTP regression tests. This constitutes an integrity hazard against malformed LLM tool arguments, rather than unauthenticated RCE.

F3 · Medium — Service Worker excludes published application path

In sw.js, the fetch event handler exits early if url.pathname.startsWith('/zerochat'). The production web deployment is hosted under /zerochat/: consequently, requests for /zerochat/zerochat.html and /zerochat/js/app.js bypass respondWith. Root-level /zerochat.html also matches this prefix check.

Executing the actual handler with synthetic events confirms that production URLs are never intercepted, whereas root /js/app.js is. Offline cache guarantees cannot function as intended under these published paths. Browser HTTP caching may provide incidental offline loads; genuine browser offline behavior remains uncertified.

Action: Disambiguate local backend API endpoints from the hosted web application base path. Add networkless reload tests targeting paths under /zerochat/ in addition to predicate unit tests.

F4 · Medium — Read limits do not bound memory or multibyte byte limits

read_file executes readlines() over the entire file before slicing specified line ranges. It subsequently truncates output by character count, despite the parameter being named max_bytes. Reading 2,000 "á" characters with max_bytes=1024 yields 2,048 UTF-8 bytes. The 1 MiB HTTP body limit protects inbound requests, not server memory overhead during file processing.

Action: Read streams incrementally, enforce encoded byte budgets, and establish strict policies for large files. Review output buffering in execute_command and result counts in list_directory, which currently lack bounded pagination budgets.

F5 · Medium / Known Design — Profile encryption does not protect secrets from file holders

profile-backup.js derives its AES-GCM encryption key from a hardcoded public constant embedded in client-side code. The module documentation acknowledges this constraint. While postMessage isolation prevents unauthorized origin interception, exported backup files cannot be considered encrypted secrets vaults. Any party possessing the backup file and application source code can extract embedded API keys.

Action: Exclude API keys from default exports and require explicit opt-in confirmation. To ensure genuine confidentiality for exported data, incorporate user-supplied passphrases. Visual profile edit locks do not provide cryptographic secret protection.

F6 · Medium / Maintenance — In-house parsers require real-world limit testing

The 2,088-line PDF parser, Markdown parser, provider adapters, and shell command tokenizer encapsulate complex contractual behaviors. PDF parsing is implemented from scratch rather than relying on PDF.js. No OCR capability exists and document extraction lacks standardized benchmarking. Orama provides lexical retrieval; parity with semantic vector embeddings is unproven.

Action: Maintain lightweight ingestion for supported document profiles and benchmark retrieval accuracy using stable test corpuses. Adopt specialized libraries or external services only when justified by broader format support requirements.

8. Security: Effective Boundary

The Python backend binds to loopback by default and mandates token authentication, providing effective protection against arbitrary local network probes. Session tokens generated with secrets.token_urlsafe(32) persist for single-day reuse via config/token.json; tokens are not regenerated per launch. Explicit 0600 file permission enforcement is absent, depending instead on user umask settings.

Directory authorization rules reside solely in the browser client. Direct authenticated requests to the Python backend do not enforce browser-side security policies. Shell executions and MCP processes run with full user system privileges. Virtual environments isolate Python package dependencies, not OS execution rights. Content Security Policy permits unsafe-inline, unsafe-eval, and broad network connections out of architectural necessity. Web Workers provide UI responsiveness, not security isolation against hostile code.

These boundaries suit a supervised personal technical workspace when documented transparently. They do not substantiate claims of a hardened sandbox for untrusted code execution. Remote exploits were not demonstrated and CVSS scores were not formally assigned.
