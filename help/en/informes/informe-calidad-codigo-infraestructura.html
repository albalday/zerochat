1. Verdict

The technical foundation remains solid for a supervised personal tool, but the permission system for local tools does not currently provide the boundaries its interface promises. Two reproduced defects let the model read or write outside authorised folders and run arbitrary commands after an apparently narrow approval. They are the most relevant risk in the product because they turn a careful user decision into a much broader grant.

Since 7.12.0 the backend has been simplified, managed MCP services have been added (Playwright, Memory, Composio with OAuth), native PowerShell support has arrived and dead code has been removed. The full suite passes (744 tests) and the privacy and RAG documentation has been corrected. The automated-browser deadlock, token permissions and static-file allowlist bypass remain open, and a new blocking issue appears in the MCP manager.

A rewrite is not justified. Fix T01–T04 before expanding tools or recommending the “Always allow” and “Trust workspace” policies. This result is not a certification or a coverage measurement.

2. Scope and method

The review covered zerochat.html, the js/ modules with the largest risk surface (permissions, MCP, Markdown, profile backups, service worker), the nine py/ modules and their match with zerochat.py, the test runner and the help. The previous audit's reproductions were repeated and targeted checks were added for 8.x changes.

Environment: Linux, Node 24.18.1, Python 3.14.7, Chromium via Playwright. Reproductions used a temporary ZEROCHAT_DATA_DIR, ephemeral loopback servers and simulated processes; no secrets were printed and no real data was touched.

Evidence types: R reproduced by execution; C checked in code or configuration. Priorities: P1 fix before expanding capabilities; P2 next consolidation block; P3 incremental improvement.

Observations with no practical impact on the intended personal use (style, module size, platform matrices that are not advertised) were omitted. No paid provider calls, external pentest, load tests or Windows/macOS installations were performed.

5. Findings and actions

T01. Folder rules treat ~ as a relative path — high, P1, R

Evidence: normalizeDirectoryPath and evaluateDirectoryRule in tool-security.js treat any path not starting with / as relative and resolve it against the startup folder. The backend applies Path(path).expanduser() in dd-tools.py. ~/.ssh/id_rsa is evaluated as <startup>/~/.ssh/id_rsa, matches the rule and is read from the home directory.

Impact: with the default configuration (empty list → R:<startup folder>) the model can read any user file without confirmation (SSH keys, tokens, ~/zerochat/config/token.json, MCP service credentials). With a W: or RW: rule it can write ~/.bashrc and gain persistent execution. The check is lexical: a symlink inside the authorised folder also leads outside it.

Action and acceptance: resolve paths with the same semantics as the backend (~ expansion, real cwd and, preferably, a final server-side check after resolve()). Reject or ask for ~, variables and non-normalisable paths. Tests: ~/x, ~user/x, an outgoing symlink and the equivalent absolute path must prompt under the default rule.

T02. Command approvals broader than they state — high, P1, R

Evidence: the “Always allow "git *"” button (tool-cards.js) stores allowedPrefixes: ["git"] with allowChaining: true and allowPipes: true, although its description says “only commands starting with "git"”. evaluateCommandConstraint only compares the start of the string, so git status; rm -rf ~/project, git log && curl … | sh or git $(…) run without asking. The rule is copied to bash and execute_command.

The “Trust workspace” policy promises to ask for “external access or global commands”, but only detects sudo, a few system directories and ../: rm -rf ~, cat ~/.ssh/id_rsa, cp x /home/u/.bashrc and curl … | sh are allowed.

Impact: a manipulated response (for example through a web page or a RAG document) can run any command with the user's permissions after an approval that looked narrow.

Action and acceptance: make command “Always allow” reject chaining, substitution and pipes unless explicitly chosen, and make its text describe exactly what is granted. Describe “Trust workspace” for what it is (a heuristic blocklist) or limit it to commands without effects outside the project. Test ;, &&, ||, |, $(), backticks, ~, $HOME and absolute user paths.

T03. One starting MCP service blocks all others — medium, P1, R

Evidence: McpServiceManager.start in ee-mcp.py holds self._lock during npm install (up to 600 s), the Playwright browser install (up to 600 s) and the handshake (150 s for Composio while waiting for OAuth). tools(), call(), stop() and configure() need the same lock.

Impact: while a service installs or waits for OAuth, no MCP tool from other services responds and the Stop button cannot cancel the startup. HTTP requests hang and the interface reports them as failures or timeouts.

Action and acceptance: update state under the lock and run installation and handshake outside it, with cancellation that terminates the running process. Test with an unresponsive service: another service's tools() and call() must answer immediately and stop() must cancel the startup.

T04. Deadlock when the automated browser fails — medium, P1, R

Evidence: PersistentBrowserSession.execute in dd-tools.py holds a threading.Lock and calls close() on EOF or exception; close() tries to acquire the same non-reentrant lock. readline() has no deadline either.

Impact: a Node or Chromium crash hangs that thread indefinitely and blocks every later browser_action call until the server restarts.

Action and acceptance: separate internal cleanup (no lock) from public close or use RLock, and add an IPC deadline. Test EOF, invalid JSON, broken pipe, silent process and later recovery.

T05. Daily session token readable by other local users — medium if local access exists, P2, R/C

Evidence: get_daily_token in cc-environment.py creates config/token.json without setting permissions (0644 with umask 022) and reuses it all day. The launch URL with #token=… is also passed as an argument to the browser launcher, visible in the process list while it runs.

Impact: another local user who can traverse the home directory obtains the token, initialises the API, receives the HMAC key and can run tools. It depends on home permissions (700 on the audited machine; 750 or 755 on other distributions).

Action and acceptance: create the directory with 0700 and the file with 0600 (fixing existing ones); consider a per-start token. Test with a permissive umask and a pre-existing file.

T06. Static-file allowlist bypass in development mode — low, P2, R

Evidence: serve_static_file in ff-server.py checks the allowlist on the path before resolving ... GET /js/../package.json returns 200 without a token; so do AGENTS.md, todo.txt and zerochat.py.

Impact: token-less reading of non-hidden files in the development repository. PyPI and curl installations, which serve no files, are not affected, and the root cannot be escaped.

Action and acceptance: apply the allowlist to the canonical relative path. Test with http.client or curl --path-as-is.

T07. execute_command timeout with another folder does not stop the work — medium, P2, R

Evidence: when cwd differs from the session, execute_command uses subprocess.run(shell=True, capture_output=True) without a process group. On timeout the shell is killed but the child keeps running (reproduced with sleep). Output is fully buffered in memory before truncation. The persistent-session branch does terminate the group.

Impact: the model and the user are told “terminated” while the command keeps changing files or consuming resources.

Action and acceptance: reuse the persistent session mechanism (start_new_session and _kill_process_tree) and bound output while reading. Test: no process from the command may remain after the timeout.

T08. Python MCP may run with the global interpreter — low, P3, C

Evidence: _prepare_service in ee-mcp.py uses sys.executable when ~/zerochat/.venv is missing, and ensure_virtual_environment continues if creation fails. This contradicts the rule that Python MCPs run only inside the venv.

Action and acceptance: mark the service unavailable with a clear error if the isolated interpreter is missing.

T09. Encryption password without salt or cost — low, P3, C

Evidence: keyMaterialFromPassword in profile-backup.js applies a single unsalted SHA-256 and the derived material is kept in localStorage for 24 hours. The help already explains that the default key is public.

Impact: an exported backup with a weak password allows fast offline dictionary attacks.

Action and acceptance: PBKDF2 with salt and iterations in a versioned format, while still reading older backups.

T10. Incomplete partial test selection — low, P3, R

Evidence: in test-runner.mjs, the generation group references tests/unit/test_generation_controller.js, which lives in tests/integration/; resolveGroupFiles silently drops missing paths, and test:changed maps changes to js/state.js or js/chat-engine.js to unit tests only.

Impact: a partial validation can pass without running relevant regressions. npm test and CI are not affected.

Action and acceptance: fix the path, fail on missing entries and include integration tests for coordination modules.

7. Repeating the review

npm test
npm audit --json
node scripts/test-runner.mjs --list

Permissions (T01, T02): load js/tool-security.js in Node, create a ToolSecurityManager, set the startup folder with setStartupDirectory and call evaluateAuthorization with read_file on ~/.ssh/id_rsa; for commands, apply setToolPolicy('bash', 'allow', …) with the constraint object the card creates and evaluate chained commands. Nothing needs to run on the system.

Backend (T03–T07): import zerochat.py with a temporary ZEROCHAT_DATA_DIR and umask 022; check the token's stat without printing it; start ThreadingHTTPServer on an ephemeral port and request /js/../package.json with http.client; create a McpServiceManager with a service that never answers initialize and time tools(); replace _ensure_running with a simulated process whose stdout is empty and run execute in a thread with a deadline; call execute_command('sleep N; …', cwd='/tmp', timeout_seconds=1) and look for the process with pgrep.

Summary: modular foundation backed by 744 passing tests; 10 prioritised findings remain. The first fixes should address folder rules and command approvals, which currently allow unconfirmed actions beyond the scope shown to the user.
