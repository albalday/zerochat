Features and maturity

Functional verdict

ZeroChat brings together a multi-model client, an agent with tools, and a local RAG in a lightweight web interface. Its conversational core shows good maturity for technical personal use. The functional scope is broad, but the level of verification varies: chat and persistence are better supported than external browsing, complex PDF extraction, WebGPU, and offline usage.

The overall assessment remains approximately at the level of the previous report: import and HTTP improvements coexist with reproducible gaps in permissions, editing, and PWA. Updating only the architecture report would be incorrect.

1. What was evaluated

A full evaluation of the current state was conducted, not merely a verification of the changelog. Product evidence comes exclusively from zerochat-master(6).zip, identified as 7.8.0 by package.json and pyproject.toml. The document informe-cambios-desde-7.6.0.md is used as a list of claims to verify, not as proof that changes work.

Previous reports were read to preserve their purpose and close their observations. Older versions of the code were not used. The ZIP contains no Git history: the eleven commits, their dates, and the release statuses cited in the changelog are not certified in this review.

Implementation reading, contracts, unit/integration and infrastructure tests, and targeted experiments are combined. "Implemented" means present in code; "tested" describes the evidence indicated in each section. No feature dependent on external services is declared universally compatible based solely on passing a mock.

Execution environment: Linux, Node.js 24.19.0, and Python 3.12.14. The declared CI uses Node.js 22 and Python 3.12; that exact matrix was not executed here. Lockfile dependencies were installed. No paid provider calls, WebGPU inference, load tests, OCR, real tests on Android/Windows/Firefox, or penetration testing campaigns were performed.

The Chromium download for Playwright failed upon receiving an invalid file. The initial global test run was interrupted following browser initialization failures; the remaining four layers ran separately to completion. The 64 declared browser test cases remain pending validation, neither passed nor imputed as product defects.

3. Conversation, models, and profiles

Conversation

Streaming, generation interruption, turn preservation, tool call pairs, editing/deletion, branches, history search, export, and IndexedDB storage are observed. The separation between engine, generation, and presentation allows testing consistency without a browser. The test suite does not replace a long conversation fluidity test on a real mobile device.

Profiles

Profiles group connection and settings, allow edit locking, and copy/import. The new transfer checks the expected window and an ID per operation; it is a concrete improvement against foreign messages or simultaneous imports. Corresponding integration tests pass.

Confidentiality: AES-GCM encryption uses a key derived from a public constant embedded in code. It hides content at first glance, but does not protect API keys from whoever receives the file. To demonstrate the product or share profiles, it is advisable to use profiles without real credentials.

4. Agent and tools

The agent has tool registration, execution, retries, cancellation, configurable limits, and context management. Tools are separated into modules with schema, execution, and presentation. Checkpoints and compaction assist long conversations; token estimates are not an exact tokenizer for all models.

The four local tools are announced on the server without prefix; the client assigns them `zmcp_*` names. Removing `max_depth` aligns the contract with actual behavior: listing is non-recursive. The editing tool writes and replaces via a temporary file, while `append` is a direct write.

5. MCP and local automation

The Python service implements discovery and tool calls and manages external MCP processes via `stdio`. Token authentication and HTTP hardening are verified improvements. Configuration is declarative per service, allowing catalog expansion without refactoring the client.

"Includes an installer" should not be confused with "all services have been certified". The bridge is also not presented as a complete implementation of every MCP capability: mainly its tool surface and stdio management were reviewed. The virtual environment does not limit what a process can read or execute.

R/W/RW rules improve daily supervision. They still need to fix composition with command restrictions, `cwd` resolution, and omitted arguments. The server does not apply rules saved in the browser to direct authenticated calls.

6. RAG and document ingestion

The implemented RAG is local and lexical. IndexedDB stores documents, chunks, and images; Orama builds derived indices, with content and title search, tolerance, and diversification. A document or corpus can be queried and chunks and images retrieved on demand. Database import/export with images is present.

This architecture avoids downloading an embedding model for standard ingestion and is suitable for personal collections where query terms match text. It does not by itself prove good retrieval of synonyms, paraphrasing, implicit relationships, or cross-questions. Neither a reliable maximum for documents, RAM, nor indexing time has been measured.

Next useful validation: set a small representative corpus, queries with known answers, and retrieval metrics (recall@k and citation precision), plus ingestion time and memory. Current tests protect implementation and regressions, but do not constitute a response quality benchmark.

7. Interface, mobility, and offline

Themes, SVGs, ES/EN dictionaries, mobile drawer, sectioned settings, responsive composer, tool panels, and debugging are present. Button resizing is present in CSS: 36 px in the desktop composer and 40 px in the inspected mobile section. That reading is not turned into an accessibility or ergonomics certification.

The PWA is partially implemented, but offline behavior has a flaw. The Service Worker precaches resources and defines an update strategy; its exclusion of routes starting with `/zerochat` avoids intercepting the app on its published route. The problem was reproduced by executing the handler, not in a real browser. Installability, manifest metadata, and offline capability are distinct properties.

The UI may be usable on mobile without mobile hosting all MCP processes. Android/Termux, mobile browsers, and WebGPU require per-platform testing. Neither WebLLM model load latency from cache nor required GPU memory has been measured here.

9. What it is ready for

Good fit

  • Technical chat with multiple providers and local data.
  • Demonstration of agentic flow, tools, context, and telemetry.
  • Personal document queries with lightweight RAG.
  • Supervised experimentation with shell and MCP servers.
  • Learning and inspecting a client whose code can be navigated.

Outside its current guarantee

  • Unattended local automation on important files.
  • Strong tool or hostile code isolation.
  • Reliable offline work on the published route before fixing F3.
  • Enterprise management with users, roles, and central auditing.
  • Universal document extraction and large-scale RAG.

To show it to other engineers, it is more compelling to demonstrate conversation, Mirror mode, a small RAG, and a low-impact tool, clearly explaining what the browser executes and what Python executes. Its value lies in the lightweight, inspectable combination, not in claiming equivalence with all major platforms.
