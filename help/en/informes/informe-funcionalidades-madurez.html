1. Verdict and evaluation criteria

ZeroChat fits well as a personal test bench for models, endpoints and tools. The 8.x series mainly strengthened tools: managed MCP services installed from the interface, OAuth authorisation for remote services, native PowerShell execution and grouped tool cards. Functional breadth is already sufficient for the goal.

What most limits local tool use today is trust in permissions: “Always allow” and “Trust workspace” grant more than they say, and the default read rule lets the model read the home directory (T01 and T02 in the technical report). For a user returning after weeks away, a guided connection diagnosis and a single view of what is stored and how to restore it are still missing.

The evaluated user is a technical person on their own machine, working under supervision on bounded tasks. Lack of team features, SSO, high availability or a full IDE is not penalised. Usability judgements are heuristic: no user sessions or paid providers were used.

3. Assessment by real task

A. “I want to test an endpoint or model for ten minutes”

High fit. Profiles, adapters, the model query from the profile magnifier and Mirror mode separate a connection failure from a model limitation. Friction remains in relating base URL, provider type, key, model and CORS when something fails.

Proposed improvement: turn the inspector query into a “test connection” flow that classifies the error (missing endpoint, 401, missing model, CORS, no tool calling) and suggests the next step.

B. “I want to compare two configurations”

Medium-high fit for manual comparison. An exportable experiment sheet (model, endpoint without secrets, effective parameters, enabled tools, metrics and date) is missing for repeating runs and explaining differences. A full evaluation lab is not recommended.

C. “I want to query some manuals or personal notes”

High fit for small material with recognisable vocabulary. The help now describes lexical search accurately. Quality is not quantified: a small set of exact, paraphrased and unanswerable questions should come before considering embeddings.

D. “I want to read and change a small project”

High fit under supervision, with an important caveat: “Always allow” for commands and “Trust workspace” should not be used today, because they authorise chained commands and home-directory paths without asking. With the “Ask” policy and a review of each call, the flow is adequate.

Proposed improvement: make each approval text state exactly what it grants and make folder rules truly confine. Acceptance: complete a task in a temporary folder with no operation outside it running without confirmation.

E. “I want to use an MCP service or a remote app”

High fit, improved in 8.x: bundled services install themselves and Composio authorises remote apps through OAuth from the browser, including on Android. The long wait is documented.

Reliability depends on T03 and T04: while a service installs or waits for OAuth, other MCP tools do not respond and the startup cannot be stopped; an automated-browser crash leaves browser_action blocked. Acceptance: start Composio without authorising and keep using Memory; stop the pending startup.

F. “I come back in a month and want my work back”

Medium fit. Profile, conversation and RAG branch exports exist but are spread across panels. MCP services do not restart on their own and a notice says so, which avoids unexpected processes. A “what is stored and where” summary with a tested restore in a clean browser is missing.

6. Proposed functional acceptance protocol

Targets for the next consolidation, not metrics obtained in this audit:

  1. With the default policy, ask the agent to read ~/.ssh/id_rsa and to run git status; echo x after “Always allow git”: both must prompt.
  2. Start Composio without completing OAuth and meanwhile use Memory tools; then stop Composio from the panel.
  3. Kill the Chromium process during browser_action and repeat the call without restarting ZeroChat.
  4. From an empty profile and a known endpoint, start a conversation in under five minutes.
  5. Cancel a slow command in another folder and confirm it is no longer running.
  6. Restore profiles, a conversation and a RAG branch in a clean browser.

7. Recommended positioning

The wording that best reflects what is implemented remains: “A personal AI test bench to connect models, inspect requests and try tools on small projects, with data stored in your browser and an optional local backend”.

The maturity needed now depends less on new features and more on approvals meaning exactly what they say and on slow or crashed external processes not blocking everything else.

Summary: good fit for personal testing, strengthened in 8.x by managed MCP services. The priority is for permissions to truly confine and for external services not to block the application.
