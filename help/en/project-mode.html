Project management

How the agent plans, tracks and documents a long-running coding project.

1. The idea

In a long project, every conversation starts without memory. ZeroChat keeps that memory in the project's own files and hands it to the agent at the start of every chat: the rules, where everything lives and where the work stands. The agent keeps it up to date as it works.

It works with the local server: the project is the directory from which zerochat.py is launched.

2. The work cycle

  1. Initialize, once. The agent reviews AGENTS.md and the documentation, tells you what already covers planning and decision records, proposes anything missing and waits for your approval. It finishes by creating ZEROCHAT.md and .zerochat/state.md.
  2. Work. Every chat starts with the rules and the current state. The agent consults the plan and the log only when it needs them.
  3. Record. When it makes a non-obvious decision or changes the plan, the agent writes it to the log and updates the state.
  4. Close a milestone. It reduces the milestone to one line in the plan, moves its log entries to .zerochat/archive/<milestone>.md and updates the state. Nothing is summarized or deleted: it is moved.
  5. Resume. The next chat, even days later or with another model, starts where the previous one left off.

3. The files

FilePurpose
ZEROCHAT.mdRules and index: where the plan, log and state live. It can simply point to AGENTS.md. Included in every chat.
.zerochat/state.mdCurrent milestone, next step and active decisions, in under 40 lines. Included in every chat.
.zerochat/plan.md, log.mdPlan and decision log, if the project does not keep them elsewhere. Read when needed.
.zerochat/archive/One file per closed milestone. Searched, not read in full.

The project's own rules are respected. Plans and logs are never stored in AGENTS.md, which other agents load in every session. ZeroChat does not decide whether .zerochat/ is versioned.

4. In the interface

  • It is on by default: if the project has a ZEROCHAT.md, it is used without doing anything.
  • A dot on the Reasoning button shows that the project is in use; a warning-colored dot means the files could not be read.
  • The Reasoning panel shows the status and actions: Initialize project, Do not use in this project, Re-enable and Reload. Its "Project mode" switch turns it off for all projects.

5. Details and limits

  • The files are read when ZeroChat opens, when the server connects and when each response finishes. If you edit them by hand, press Reload.
  • Initialization grants read and write access only to .zerochat/; any other write follows the current authorization policy.
  • Contents are treated as repository data, not privileged instructions, and each file is read up to 16 KB.
  • The rules and state survive history compaction; the summary flags anything not yet recorded.
  • The system organizes information, but it does not guarantee that the model follows it. Review what it proposes, especially with small models.
