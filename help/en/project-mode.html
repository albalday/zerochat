Project management

How the agent plans, tracks and documents a long-running coding project.

1. The idea

In a long project, every conversation starts without memory. ZeroChat keeps that memory in the project's own files and hands it to the agent at the start of every chat: the rules, where everything lives and where the work stands. The agent keeps it up to date as it works.

The rules, including how to keep the memory, live in AGENTS.md, the file that Codex, Cursor, Copilot and other agents also read. That way any agent working on the project follows the same plan and keeps it the same way.

It works with the local server: the project is the directory from which zerochat.py is launched.

2. The work cycle

  1. Initialize, once. The agent reviews AGENTS.md, other agents' files (CLAUDE.md, .cursorrules…) and the documentation, and tells you what already covers planning and decision records. It then proposes the changes and waits for your approval: creating AGENTS.md if it does not exist or adding the Project memory section to it, and making other agents' files point to it. If the project has no plan, it asks you for its purpose, which it writes in README.md, and its first milestone. It finishes by creating .zerochat/state.md.
  2. Work. Every chat starts with the rules and the current state. The agent consults the plan and the log only when it needs them.
  3. Record. Before starting work that is not in the plan, the agent adds it as a task. Right after finishing each task, before starting the next one, it marks it in the plan, writes its non-obvious decisions to the log and sets the next task in the state. That way, if the session is cut short, the memory reflects what was done.
  4. Close a milestone. The agent asks you before closing a milestone or adding a new one, which always has a goal and done-when criteria. When closing it, it reduces the milestone to one line in the plan, moves its section to .zerochat/archive/M<n>.md and updates the state. Nothing is summarized or deleted: it is moved. The decision log is not archived, because decisions stay in force after the milestone.
  5. Resume. The next chat, even days later or with another model, starts where the previous one left off.

3. The files

FilePurpose
AGENTS.mdProject rules for every agent; if details live in other documents, it links them. Its Project memory section explains how to keep the memory. Included in every chat.
.zerochat/state.mdCurrent milestone, next task and active decisions, in under 40 lines. Included in every chat. Its existence marks the project as initialized.
.zerochat/plan.mdMilestones and their tasks, if the project does not keep its plan elsewhere. Read when needed.
.zerochat/log.mdDecision log, one line per decision. Append only and never archived. Searched, not read in full.
.zerochat/archive/The plan section of each closed milestone. Searched, not read in full.

CLAUDE.md and other agents' files only point to AGENTS.md; CLAUDE.md uses the line @AGENTS.md, which imports it. Plans and logs are never stored in AGENTS.md, which agents load in every session. ZeroChat does not decide whether .zerochat/ is versioned.

Tasks and decisions

Each task takes one line with an ID numbered within its milestone. Marking it done only takes editing that line:

- [ ] M2-T3 Export the conversation to PDF
- [x] M2-T3 Export the conversation to PDF (2026-10-09)

IDs are never renumbered or reused, and the plan and log are never rewritten as a whole. Decisions are appended to the log with their own ID and the task that prompted them: - 2026-10-09 M2-D1 Use the browser's print dialog (M2-T3).

4. In the interface

  • It is on by default: if the project has a .zerochat/state.md, it is used without doing anything.
  • A dot on the Reasoning button shows that the project is in use; a warning-colored dot means the files could not be read.
  • The Reasoning panel shows the status and actions: Initialize project, Do not use in this project, Re-enable and Reload. Its "Project mode" switch turns it off for all projects.

5. Details and limits

  • The files are read when ZeroChat opens, when the server connects and when each response finishes. If you edit them by hand, press Reload.
  • Initialization grants read and write access only to .zerochat/; any other write, such as to AGENTS.md, follows the current authorization policy.
  • If .zerochat/state.md still has the template placeholders, the agent asks you to complete it and the plan before going on.
  • If AGENTS.md or its Project memory section is missing, the agent proposes adding it. Place it at the top of the file: 16 KB are read.
  • Contents are treated as repository data, not privileged instructions, and each file is read up to 16 KB.
  • The rules and state survive history compaction; the summary flags anything not yet recorded.
  • The system organizes information, but it does not guarantee that the model follows it. Review what it proposes, especially with small models.
