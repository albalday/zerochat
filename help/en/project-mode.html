Project mode

The rules, plan and state of a long-running coding project, present in every chat.

1. What it does

Project mode keeps a project's memory in the project's own files, not in the browser. On every request, ZeroChat adds the contents of ZEROCHAT.md and .zerochat/state.md to the system prompt. The agent uses them to know which rules to follow, where the plan and decision log live and where the work stands, and updates them when it closes a milestone or makes a decision.

It requires the local server. The project is the directory from which zerochat.py is launched: one server per project. Without the server, the mode has no effect.

2. Project files

FileContents
ZEROCHAT.mdRules and an index of the sources of truth: where the long- and short-term plans and the milestone and decision log live. It can simply point to AGENTS.md. Meant to be versioned. Injected into every chat.
.zerochat/state.mdCurrent state: milestone in progress, next step and active decisions, in under 40 lines. Injected into every chat.
.zerochat/plan.md, .zerochat/log.mdPlan and decision log, only if the project does not already keep them elsewhere. Read when needed.
.zerochat/archive/One file per closed milestone with its plan detail and log entries. Searched, not read in full.

To keep the plan and log from growing without limit, when a milestone closes the agent reduces it to one line in the plan, moves its entries to .zerochat/archive/<milestone>.md and updates state.md. Nothing is summarized or deleted: it is moved. Plans and logs are not stored in AGENTS.md, which other agents load in every session; it only receives short rules and pointers.

You decide whether .zerochat/ is versioned or added to .gitignore. The project's own rules, such as AGENTS.md, are respected and never replaced.

3. Enabling and initializing

The mode is on by default: as soon as the project has a ZEROCHAT.md, it is used without going through any menu. The switch in the composer's Reasoning panel turns it off; it is a global preference that does not change when switching profiles.

While the project is being injected, the reasoning button shows a colored dot; if the mode is on but the files cannot be read, the dot turns to a warning color. The button tooltip names the project and its status. The panel shows the details:

  • Active: ZEROCHAT.md was read and is injected into every chat. Reload reads the files again.
  • No ZEROCHAT.md: offers Initialize project and Do not use in this project.
  • Disabled for the project: you declined it; Re-enable in this project undoes that.
  • No read permission or requires the local server: nothing is injected.

Initialize project asks for confirmation, grants read and write access only to .zerochat/ and sends the agent a visible message with the start-up instructions, in a new conversation if the active one has content. The agent first reviews AGENTS.md and the existing documentation, reports what already covers planning and decision records, proposes anything missing and waits for your approval before writing. It finishes by creating ZEROCHAT.md and .zerochat/state.md.

The files are read when ZeroChat opens, when the server connects and when each response finishes, so the agent's changes are picked up for the next message. If you edit them by hand, press Reload.

4. Permissions and security

  • Reading uses read_file with the working directory's read rule, which exists by default. If you remove it, ZeroChat does not ask in every chat: it shows "no read permission".
  • Initialization adds the rule RW:<project>/.zerochat. Any write outside that folder, including ZEROCHAT.md and AGENTS.md, follows the current authorization policy.
  • File contents are treated as repository data, not privileged instructions: in a conflict, your messages and the system rules prevail. Each file is read up to 16 KB.

5. Compaction and limits

Because the rules and state live in the system prompt, they survive automatic history compaction. With the mode active, the summary adds a "Pending project records" section listing decisions and milestones not yet written, so the agent records them in the next step. No summary writes to the project on its own.

Project mode organizes information, but it does not guarantee that the model follows it or keeps the files up to date. Review the changes it proposes, especially with small models.
