Model Context Protocol (MCP)

Local server, MCP services and permission scope.

Local tools have names such as read_file or execute_command. External tools use <service>_<tool>. Permissions are associated with the full name; authorizing one tool does not authorize an identically named tool in another service.

1. What MCP is

MCP enables discovery and invocation of tools in other processes. In ZeroChat, the local server connects the browser interface to computer tools and managed external services.

For this workflow, start zerochat or python3 zerochat.py. The server listens on the local interface and opens the web app with a session token. Without it, you can still use chat and available browser tools.

2. Connection and status

Open Settings → MCP to see status and discovered tools. There is no manual connection form: use the link opened by the startup command.

If disconnected, check that the process is running, reopen its link and review browser permissions for local network access. Do not share the startup link containing its token.

3. Local server

Install the executable from PyPI or download the script. Outside the development repository, both open the GitHub Pages interface and store their state in ~/zerochat/.

# PyPI
pip install zerochat && zerochat

# Direct download
curl -sL https://albalday.github.io/zerochat/zerochat.py -o zerochat.py && python3 zerochat.py

Startup prepares config/, services/ and .venv/ for Python MCP services. Review warnings if environment creation fails before starting services. The main executable keeps using the interpreter that launched it.

  • list_directory: lists directories, with bounded recursive traversal.
  • read_file: reads text with line ranges and size limits.
  • write_file: creates or overwrites files.
  • edit_file: replaces a passage that must match exactly once; compatibility modes are also available.
  • search_files: searches text or regular expressions in files.
  • bash and execute_command: run commands; the shell session may retain its directory and variables between calls.
  • get_diagnostics: gathers available syntax checks; it does not replace project tests.
  • browser_action: automates Chromium when its requirements are installed.

MCP requests carry the token in headers. Tool calls additionally require short-lived, single-use signed authorization. The local token is retained per day; the signing key changes when the process restarts.

If the terminal shows [i] information, press i to read notices such as an available update.

4. Permissions

In Settings → Permissions, choose the global policy and review remembered rules and trusted servers. The MCP panel lets you enable tools and choose Ask, Allow or Deny.

  • Ask for authorization: asks when existing rules do not resolve a call.
  • Workspace trust: permits operations matching directory rules; it does not create an isolated machine.
  • Allow all: permits execution without confirmation, except for higher-priority explicit blocks.

The Permissions panel uses open sections with subtle separators and soft backgrounds for policies and saved authorizations. Headings and details adapt to the available width.

Decisions can apply to one call, the backend session or permanently. Trusting a server authorizes more than one tool. Review the scope before remembering it.

Authorization dialogs identify the originating service of each external MCP tool. Trusting composio authorizes its tools without authorizing tools from other external services. Individual authorization applies only to the selected tool.

Allowed directories accepts one rule per line: R: for read, W: for write and RW: for both, with * for one segment and ** for subdirectories. An empty list inserts a read rule for the startup directory. Commands have prefix rules and additional checks.

These permissions are not an operating-system container. An authorized command or service acts with the local process permissions and may make changes outside the intended target. Review arguments and keep backups or version control; stopping a call does not undo its effects.

5. External MCP services

In Settings → MCP → Available MCP servers, configure, start or stop each service. When you select Start, ZeroChat automatically installs the npm package and its dependencies in the service's own directory. If a requirement cannot be prepared, the card displays the error and links to this section. Services enabled in a previous session are not restarted automatically; when connected, ZeroChat shows a notice so you can start them from this section after checking for web updates. If you accept reloading to update, the notice appears on the next startup.

The panel separates sections with headings and subtle lines, and highlights each server with a soft background. On mobile, connection status and counters adapt to the available width, and actions appear below the description.

  • ejemplo: bundled template for creating managed MCP services; it does not download dependencies. Its card links to this guide.
  • composio: remote connection through mcp-remote to the Composio Connect endpoint. It requires Node.js 18+ and npm; ZeroChat installs the bridge in the service's own directory. When an app such as Gmail is used, Composio presents its OAuth authorization in the browser. The bridge's credentials and OAuth state remain isolated in the service directory.
  • playwright: requires Node.js 18+ and npm. ZeroChat installs @playwright/mcp and Chromium. Downloading Chromium requires network access and disk space. If browser_action is active, ZeroChat asks for confirmation before disabling it and replacing it with the complete Playwright toolset.
  • memory: requires Node.js 18+ and npm. ZeroChat installs @modelcontextprotocol/server-memory and its dependencies.

If installation fails, check the stated Node.js version with node --version, confirm that npm --version works, and check npm network access and free disk space. Fix the requirement and select Start again; reinstalling ZeroChat is not necessary.

Services are managed under ~/zerochat/services/. Deleting ~/zerochat/ removes this state and its dependencies, but not browser history or files changed outside that folder.

On Termux, ZeroChat prepares an xdg-open bridge so MCP services open authorization links with termux-open-url.

At startup, ZeroChat restores its bundled configuration files for ejemplo, composio, playwright, and memory. It keeps their installed dependencies and data, as well as service folders created by the user.

Creating an MCP service with an agent

Use ~/zerochat/services/ejemplo/ as the reference structure. Each service needs service.json; add installer.json only when ZeroChat must install an npm package. The optional standard help field lets JSON define a visible link on the service card:

"help": {
  "url": "help/mcp.html#crear-mcp-con-agente",
  "label": { "es": "Guía del servicio", "en": "Service guide" }
}

The URL must be a ZeroChat-relative path or an https: or http: URL.

Creating a local MCP (stdio)

Copy this prompt and replace <mcp-name>. The model creates the definition; you enter the key and start the service:

I want to create the local MCP <mcp-name> for ZeroChat.
Locate the user's home directory and read README.md, service.json
and installer.json.example in zerochat/services/ejemplo using
absolute paths. Follow the README instructions.
Read the MCP's official documentation and create a sibling folder
with its own name and id; do not modify the bundled services.
If it needs an API key, put PASTE_API_KEY_HERE in launch.env,
under the variable name required by the MCP. Do not ask for my key.
Give me the absolute JSON path and the field to edit manually.
Do not install or start it; I will do that from Settings → MCP.

Creating a remote MCP (HTTP/SSE)

Use Composio as an example of a local mcp-remote bridge. The connection to ZeroChat remains stdio; the bridge connects to the remote endpoint. Copy this prompt and replace the name and URL:

I want to create the remote MCP <mcp-name> for ZeroChat.
Its endpoint is <mcp-url>.
Locate the user's home directory and read README.md in
zerochat/services/ejemplo and the JSON files in
zerochat/services/composio using absolute paths. Follow the README
and use Composio as an example of a managed stdio mcp-remote bridge.
Create a sibling folder with its own name and id and bilingual text.
Read the MCP's and bridge's official documentation to adapt the
endpoint, transport and authentication. Verify Composio's specific
OAuth and protocol options before copying any of them.
Keep HOME and USERPROFILE isolated inside ${serviceDir}.
If an API key is required, put PASTE_API_KEY_HERE in launch.env
and configure --header with the provider's required header and a
reference to that variable; mcp-remote will resolve the reference.
Do not ask for my key or put it in the arguments or URL.
Give me the absolute JSON path and the field to edit manually.
Do not install or start it; I will do that from Settings → MCP.

Entering and keeping an API key

  1. Create your own folder under ~/zerochat/services/, with service.json and, if it needs npm, installer.json. Use the prompts above or copy an existing service definition, without copying its dependencies or OAuth credentials.
  2. When copying a definition, change the folder name, JSON id and visible text. The id must be unique. Adapt the endpoint and authentication to the provider's documentation; changing the key alone does not switch OAuth to API key authentication.
  3. Open your folder's service.json and replace PASTE_API_KEY_HERE with the real key inside launch.env. Use the exact variable name expected by the MCP. Do not paste the key into the chat.
  4. Save valid JSON, preserving the rest of launch. On Linux and Termux restrict file access with chmod 600 /absolute/path/zerochat/services/my-service/service.json. The key is stored in plain text: do not share the file or commit it to a repository.
  5. Open Settings → MCP and select Start. If the new folder does not appear, restart ZeroChat and reconnect. To change the key of a running service, stop it, edit the JSON and start it again.

Example of a field inside launch for a local MCP; replace the variable name with the one specified by the provider:

"env": {
  "SERVICE_API_KEY": "PASTE_API_KEY_HERE"
}

You do not need export, a .env file or a separate credentials JSON. ZeroChat passes the value written in launch.env to the MCP process. ${SERVICE_API_KEY} in that field would remain literal text: ZeroChat only replaces service/interpreter paths and ${option:...} references.

For a remote endpoint accepting Authorization: Bearer, adapt the bridge arguments and add the key to the existing env, preserving HOME and USERPROFILE:

"args": [
  "${serviceDir}/node_modules/mcp-remote/dist/proxy.js",
  "https://mcp.example.com/mcp",
  "--header",
  "Authorization: Bearer ${REMOTE_API_KEY}"
],
"env": {
  "HOME": "${serviceDir}",
  "USERPROFILE": "${serviceDir}",
  "REMOTE_API_KEY": "PASTE_API_KEY_HERE"
}

Here mcp-remote, rather than ZeroChat, resolves ${REMOTE_API_KEY} in the header. If the provider requires another header, such as X-API-Key, use that header and its format. The remote.authentication field describes the service for the UI; it does not configure authentication. See the bridge's official custom header documentation.

Your own folder's files survive ZeroChat restarts and updates. Do not edit JSON files in bundled folders (ejemplo, composio, playwright and memory): they are restored on every startup. Deleting ~/zerochat/ also removes your services and keys; keep a private backup if needed.

Patches in a series such as 8.0.x arrive with the web app. A major.minor change may require updating the backend. Follow the notice for PyPI or direct download; updates are not automatic.
