Local server and MCP

Local server, MCP services and permission scope.

1. Start and connect

MCP connects the chat to computer tools and external services. You need the local ZeroChat server. Choose one installation method:

PyPI (recommended)

pip install zerochat && zerochat
On Windows: If the zerochat executable is not on your PATH, run directly using py -m zerochat (or python -m zerochat).

Direct download

curl -sL https://albalday.github.io/zerochat/zerochat.py -o zerochat.py && python3 zerochat.py

For subsequent launches, use zerochat (or py -m zerochat on Windows) or python3 zerochat.py, respectively. Both open GitHub Pages and store local data in ~/zerochat/.

  1. Keep the server running and open the link it provides.
  2. Go to Settings → MCP and check the connection and discovered tools.
  3. Enable the tools you need and review their permissions.

If disconnected, check that the process is running, reopen its link and review the browser's local network access permissions. There is no manual connection form. Do not share the startup link containing its token.

Browser compatibility: ZeroChat does not support WebKit (Safari and every browser on iPhone/iPad). On macOS use Firefox or a Chromium-based browser. More details. Tested environments: Linux, Windows (PowerShell) and Android (Termux).

2. Use computer tools

  • Files: list_directory, read_file, write_file, edit_file and search_files.
  • Commands: bash and execute_command. The shell session retains its working directory and environment variables across calls. On Linux/macOS/Android it uses bash/sh; on Windows it runs natively in PowerShell providing host OS context to the model.
  • Syntax checks: get_diagnostics; it does not replace project tests.
  • Browser: browser_action requires Node.js and having Chrome or Edge on your system (or Chromium). To use it, start the Playwright service in Settings → MCP (it installs automatically). See the setup guide.

Tool results become part of the conversation and may be sent to the selected model.

3. Start an external MCP service

In Settings → MCP → Available MCP servers, configure each service and select Start. ZeroChat prepares its declared dependencies. To stop a service, select Stop.

Included servicePurpose and requirements
ejemploTemplate for custom services; no dependency downloads.
composioRemote apps through mcp-remote and OAuth; Node.js 18+ and npm.
playwrightBrowser automation; Node.js 18+, npm and Chromium. If browser_action is active, ZeroChat asks before replacing it.
memoryMemory and knowledge graphs; Node.js 18+ and npm.

Startup and OAuth

The button shows Starting and stays disabled. If startup exceeds 15 seconds, ZeroChat checks the status and waits for up to ten additional 15-second intervals while it remains installing or starting. Installation and the OAuth wait are not treated as failures when the first timeout expires; once the service is active, the panel updates automatically. The button shows the attempt number.

If the service needs OAuth, its card shows an Authorization required notice with an Authorize in browser button. ZeroChat tries to open the authorization tab; if the browser blocks it, press the button. Because it opens from the web page itself, it also works on Android and Termux. If the wait expires, the service may still be starting; reload the page to check the outcome.

Services are not restarted automatically on the next ZeroChat startup. If any were enabled, a notice reminds you when connecting; start them from this panel when needed.

If installation fails

Read the card's error. Check node --version, npm --version, network access and free disk space, then try again. You do not need to reinstall ZeroChat.

4. Review permissions

In Settings → Permissions, choose the global policy and review saved authorizations. In the MCP panel, choose Ask, Allow or Deny for each tool.

  • Ask for authorization: prompts when existing rules do not resolve the call.
  • Trust the workspace: allows operations matching directory rules.
  • Allow everything: runs without confirmation, except for explicit blocks that take precedence.

Decisions may apply to one call, the backend session or permanently. External tools are named <service>_<tool>: trusting composio authorizes its tools, not those of other services. Allowing one tool does not authorize the whole service.

Allowed directories: one rule per line, with R: (read), W: (write) or RW: (both). Use * for one segment and ** for subdirectories. An empty list adds a read rule for the startup directory. Commands also have prefix rules and additional checks.

These rules are not an operating system sandbox. Authorized commands and services act with the local process's permissions. Stopping a call does not undo its changes.

5. Add your own service

Create a new folder under ~/zerochat/services/ with its own name and unique id. Use ejemplo as the template: service.json is required; add installer.json only for npm packages. The template's README.md documents the fields, including an optional help link.

You can ask the agent to create the definition using either prompt below. Replace the placeholders. The agent prepares files; you enter credentials and start the service.

Prompt for a local MCP (stdio)

Locate the user's home directory and read README.md, service.json
and installer.json.example in zerochat/services/ejemplo using
absolute paths. Follow the README instructions.
Read the MCP's official documentation and create a sibling folder
with its own name and id; do not modify the bundled services.
If it needs an API key, put PASTE_API_KEY_HERE in service.json,
inside the env object under launch, using the required variable.
I will manually replace the placeholder with my key in service.json.
Do not ask for my key or create a launch.env or .env file.
Give me the absolute JSON path and the field to edit manually.
Do not install or start it; I will do that from Settings → MCP.

Prompt for a remote MCP (HTTP/SSE)

The managed mcp-remote process uses stdio with ZeroChat and HTTP/SSE with the provider. Use Composio as a bridge example, adapting its authentication to the new provider.

I want to create the remote MCP <mcp-name> for ZeroChat.
Its endpoint is <mcp-url>.

OAuth and protocol options before copying any of them.

inside the env object under launch. I will enter my key manually

If the new folder does not appear in Settings → MCP, restart ZeroChat and reconnect. Your own folders survive updates. Bundled definitions (ejemplo, composio, playwright, memory) are restored at startup; create a copy with a new name and id instead of editing them. Do not copy dependencies or OAuth credentials.

6. Enter an API key

launch.env means the env object under launch in service.json; it is not a file. The agent leaves the placeholder and you manually enter the real key in that JSON.

  1. Stop the service if it is running. Open your folder's service.json.
  2. Replace PASTE_API_KEY_HERE inside launch.env with the real key, using the exact variable name required by the provider. Do not paste it into the chat.
  3. Save valid JSON. On Linux or Termux restrict access with chmod 600 /absolute/path/zerochat/services/my-service/service.json.
  4. Start the service from Settings → MCP.

The key is stored in plain text: do not share or commit this file. Deleting ~/zerochat/ also removes services and credentials; keep a private backup if needed.

Example for a local service

Inside launch, use the variable name specified by the MCP:

"env": {
  "SERVICE_API_KEY": "PASTE_API_KEY_HERE"
}

No export, .env file or extra credentials JSON is needed. Write the actual value in launch.env; environment variable references there remain literal text. ZeroChat expands service/interpreter paths and ${option:...} references.

Example for a remote service with a Bearer header

Adapt the bridge arguments and preserve the existing HOME and USERPROFILE isolation:

"args": [
  "${serviceDir}/node_modules/mcp-remote/dist/proxy.js",
  "https://mcp.example.com/mcp",
  "--header",
  "Authorization: Bearer ${REMOTE_API_KEY}"
],
"env": {
  "HOME": "${serviceDir}",
  "USERPROFILE": "${serviceDir}",
  "REMOTE_API_KEY": "PASTE_API_KEY_HERE"
}

mcp-remote resolves ${REMOTE_API_KEY} in the header. Use the provider's required header and format. remote.authentication is descriptive; it does not configure authentication. See the bridge header documentation.
