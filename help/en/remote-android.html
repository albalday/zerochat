Use your home server from Android

An SSH tunnel brings the home computer's tools to the tablet or phone browser.

1. How it works

The interface loads from GitHub Pages in the Android browser and talks to 127.0.0.1:6883 on the tablet itself. The SSH client (ConnectBot or Termux) forwards that port to 127.0.0.1:6883 on the home computer, where the local server runs. Files, commands and MCP services are therefore the home computer's.

  • ZeroChat stays private: the server still listens only on 127.0.0.1; only SSH is reachable from outside.
  • Port 6883: different from the default 6388, so the desktop ZeroChat and the tablet one can run side by side.
  • Model at home: if you use LM Studio or another model server on the same computer, forward its port too (1234 for LM Studio) and point the profile to http://127.0.0.1:1234/v1.

2. Prepare the home computer

Harden sshd

In /etc/ssh/sshd_config (or a file in /etc/ssh/sshd_config.d/), keys only and your user only; then restart the service (sudo systemctl restart sshd):

PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
AllowUsers user
AllowTcpForwarding local

Launch script

Save it as ~/bin/zerochat-tablet.sh and make it executable with chmod 700 ~/bin/zerochat-tablet.sh. It starts ZeroChat without a browser (or reuses the one already running), reads the daily token from ~/zerochat/config/token.json and prints the URL to open on the tablet.

#!/usr/bin/env bash
# Starts ZeroChat at home without a browser (or reuses the running one) and prints
# the URL with the daily token to open in the tablet browser.
# Meant to run from ConnectBot over SSH (also works as a forced command=).
set -euo pipefail

PORT="${ZEROCHAT_PORT:-6883}"            # must match the port forwarded in ConnectBot
DATA_DIR="${ZEROCHAT_DATA_DIR:-$HOME/zerochat}"
TOKEN_FILE="$DATA_DIR/config/token.json"
LOG="$DATA_DIR/tablet-server.log"
ZEROCHAT="${ZEROCHAT_BIN:-zerochat}"
UI_URL="https://albalday.github.io/zerochat/zerochat.html"

read_token() {
    python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["token"])' "$TOKEN_FILE" 2>/dev/null
}

# 200 = ZeroChat server with this token; 401 = another token; 000 = nothing listening.
probe() {
    curl -s -o /dev/null -w '%{http_code}' --max-time 3 \
        -H "Authorization: Bearer ${1:-x}" "http://127.0.0.1:$PORT/zerochat/heartbeat" || true
}

start_server() {
    echo "Starting ZeroChat on 127.0.0.1:$PORT..."
    # --keep-server: the mobile browser stops sending heartbeats in the background and,
    # without it, the server would shut down 60 s after switching apps.
    # setsid + nohup: survives the end of the SSH session.
    cd "$HOME"
    setsid nohup "$ZEROCHAT" --no-browser --keep-server --port "$PORT" \
        </dev/null >>"$LOG" 2>&1 &
    for _ in $(seq 1 60); do
        sleep 0.5
        token="$(read_token || true)"
        [ -n "$token" ] && [ "$(probe "$token")" = 200 ] && return 0
    done
    echo "ZeroChat did not respond within 30 s. Last lines of $LOG:" >&2
    tail -n 20 "$LOG" >&2
    exit 1
}

token="$(read_token || true)"
case "$(probe "$token")" in
    200) echo "ZeroChat was already running on port $PORT." ;;
    000) start_server ;;
    401)
        # A ZeroChat with a different token (e.g. yesterday's, and another process renewed token.json).
        echo "The ZeroChat on port $PORT uses another token: restarting it."
        pkill -f -- "/zerochat --no-browser --keep-server --port $PORT\$" || true
        sleep 2
        start_server ;;
    *)  echo "Port $PORT is in use by another program." >&2; exit 1 ;;
esac

token="$(read_token)"
url="$UI_URL#token=$token&host=127.0.0.1&port=$PORT"
echo
echo "Open on the tablet:"
echo "$url"
echo
# Keeps the session open (the tunnel lives as long as the ConnectBot session).
if [ -t 0 ]; then
    echo "Tunnel active. Press Ctrl+C or close the session to stop it (ZeroChat keeps running at home)."
    trap 'exit 0' INT
    while sleep 3600; do :; done
else
    exec sleep infinity
fi
  • Path to zerochat: an SSH session with a forced command does not load your full PATH. If zerochat is not in /usr/bin, set its full path, as shown by command -v zerochat, in ZEROCHAT_BIN at the top of the script.
  • --keep-server: the Android browser stops sending heartbeats when the tab goes to the background; without this option the server would shut down a minute after switching apps.
  • Log: the server output goes to ~/zerochat/tablet-server.log.

Restricted key

Create a key pair just for the tablet and add the public key to ~/.ssh/authorized_keys with these restrictions, on a single line. It can only open the tunnel to those two ports and launch the script, with no console or other commands:

restrict,port-forwarding,permitopen="127.0.0.1:6883",permitopen="127.0.0.1:1234",command="/home/user/bin/zerochat-tablet.sh" ssh-ed25519 AAAA… tablet

3. Connect from Android

ConnectBot

  1. In ConnectBot's public keys, generate an Ed25519 key and copy its public part to the home authorized_keys (section 2).
  2. Create the host user@home with that key.
  3. In the host's port forwards, add two of type Local: 6883 → 127.0.0.1:6883 and 1234 → 127.0.0.1:1234.
  4. Connect. The console shows the URL; copy it and open it in the browser. The session accepts no commands: it only keeps the tunnel open.

Without the restricted key, you can put ~/bin/zerochat-tablet.sh in the host's post-login automation to launch it on connect.

Termux

Without -N, so the script runs and prints the URL:

ssh -i ~/.ssh/tablet -L 6883:127.0.0.1:6883 -L 1234:127.0.0.1:1234 user@home

In the browser

  • Local network access: if the browser asks to let the page access devices on the local network, allow it; without it the page cannot reach 127.0.0.1.
  • Separate configuration: profiles, API keys and conversations are stored in the tablet browser, apart from the desktop ones. Create the profile for the home model there.
  • Token in the URL: anyone with the URL and the tunnel open can use the home computer's tools. Do not share the URL.

4. Common situations

SituationWhat happens
ZeroChat is already running on 6883The script reuses it and prints its URL again.
The running server uses another day's tokenThe script stops it, starts it again with today's token and prints the new URL. Reload the page with it.
Another program is using 6883The script exits with an error: Port 6883 is in use by another program.
The SSH connection dropsZeroChat keeps running at home. Reconnect and reload the page. To stop it: pkill -f -- '--keep-server --port 6883'.
Tools fail with 403 Expired or invalid tool authorizationThe tablet and home clocks differ by more than 15 s. Turn on automatic date and time on both.
