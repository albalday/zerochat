WebLLM & WebGPU Configuration

Preparing a browser model and understanding WebGPU limitations.

What WebLLM does

WebLLM runs a model inside the browser using WebGPU. Inference needs no remote API, but initial preparation downloads the runtime and weights. Web or MCP tools may still communicate with external services.

Offline operation depends on all application and model resources being available in cache. Opening the page once does not guarantee it. See the WebLLM guide.

Hardware requirements

You need a browser with working WebGPU, a compatible graphics adapter and enough memory. The catalogue shows a memory estimate for each model; context and prompt processing add to usage.

Start with a small model and a moderate window. WebGPU availability does not guarantee that a particular model fits on the GPU or works with its drivers.

Browser Configuration & WebGPU Setup

Chrome, Edge and Chromium

Use an up-to-date version, review graphics acceleration in browser settings and check WebGPU status on its diagnostic page, for example chrome://gpu.

Experimental flags are not a routine setup requirement. Forcing options that bypass driver checks can introduce failures and does not solve missing memory or device support.

Firefox

Availability depends on the version, operating system, GPU and drivers. Review about:support and check whether ZeroChat detects WebGPU.

Changing advanced preferences or ignoring driver blocks is not a general requirement. If usable WebGPU is unavailable, use a compatible environment or an inference server profile.

Using WebLLM in ZeroChat

  1. Create or edit a profile and select WebLLM.
  2. Press Query to open the catalogue. Completed models appear first.
  3. Download a model and wait for preparation to finish. An incomplete download does not count as available.
  4. Select the model and save the profile. If already downloaded, you do not need to repeat Query to save it.

Initial preparation can take time and occupy several gigabytes. Cache belongs to the browser and origin used; another browser may need a new download.

Performance parameters

The WebLLM profile gear control lets you adjust context_window_size and prefill_chunk_size (the prompt processing block size).

The context window accepts 16K, 32K, 64K (default) and 128K. For prefill, Model default retains its configuration. Increasing context consumes more memory. Changing prefill may affect speed and memory without guaranteeing an improvement. If preparation fails, return to defaults or try a smaller model.

Resetting settings and freeing space

1. Chrome, Edge and Chromium

If you changed a flag, reset that option to Default and restart. Avoid resetting all browser options when you changed only one.

2. Firefox

If you changed a WebGPU preference, use its reset control in about:config. Defaults depend on the version: do not replace them with a fixed value from an old guide.

3. Downloaded models

Use the catalogue delete action to remove a model. To reset all storage, Settings → Clear all deletes data for the current origin, including conversations, profiles, RAG, attachments and models. Export what you want to keep and close other tabs before confirming.

This does not delete files downloaded to disk, HttpOnly cookies or the browser's internal HTTP cache. Data for different origins is separate.

Common problems

  • WebGPU unavailable: check browser, secure context (HTTPS or localhost), drivers and graphics acceleration.
  • Out of memory: close other GPU workloads, reduce context or choose a smaller model.
  • Download or preparation error: read the complete error in the model row, check network and space, and retry.
  • Missing cache: private browsing, site cleanup or browser quotas may remove resources. Cache is not guaranteed permanent storage.

Compatibility must be checked on the actual device. A model may support chat without supporting vision, tools or another provider's reasoning settings.
