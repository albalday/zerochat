Review 2: Features

What ZeroChat 10.16.0 does, which test backs it and what changes when running on the server. Updated on 14 November 2026.

1. Goal and method

ZeroChat aims to be the single frontend for local models served separately through OpenAI-compatible APIs (vLLM, llama.cpp, LM Studio, SGLang) or Ollama. The review walks through the capabilities of version 10.16.0 (commit 865cbba) in the code, not in the documentation.

The 10.x series turns the local server into the home of the work: it stores conversations and profiles, runs agent turns in the background even with the browser closed, decides permissions and separates state by project. The web interface becomes a view that can be opened from several devices.

Each capability states what protects it: [test] an automated test or [reading] code review.

3. Two execution environments

Since 10.8 the same agent loop runs in two places, and they do not offer the same. It is worth keeping in mind when choosing "Run on server".

CapabilityIn the browserOn the server (Node.js)
ProvidersAll, including WebLLMRemote APIs and model servers; no WebLLM
Machine tools and MCPYes, with authorization challenges on screenYes; a challenge pauses the run until it is answered
RAGYesNo
execute_javascriptOpaque-origin iframe with no networkSeparate Node process with no disk, environment or token, killed by signal when the timeout expires
Reading pages and Word filesThe browser's DOMParserThe project's own lightweight HTML parser, bounded in depth

The separation is well solved in the code, with environment adapters instead of scattered conditionals [reading], but the help does not gather these differences in a table like this one.

6. Limits

  • Single user: one system account per server; multi-user means one server per person.
  • Two copies of the data: SQLite on the server and IndexedDB in each browser, with no built-in backup of the server.
  • Server runs: they need Node.js and include neither RAG nor WebLLM.
  • Lexical RAG, with no vector similarity.
  • Browsers: Chromium and Firefox; WebKit is not supported.
  • Windows and macOS: the backend is tested on both in CI; the interface and the Node runner, on Linux only.
  • Configuration complexity: local and server profiles, a project per tab and permissions in three scopes require understanding the model before getting the most out of it.

7. Verdict

A working environment that lives on the server, with one execution environment more mature than the other. ZeroChat 10.16.0 lets you start a task, close the browser and pick it up from another device, with history and permissions in one place and separated by project. In this version server runs gained page and Word reading, tool batches with images and a process with restricted permissions. In 10.16.0 it matches the browser where security matters: the runner has a credential limited to its run and the model's JavaScript runs in a separate process with no credential; it still lacks RAG and WebLLM. The price of the whole is a product that is harder to explain and two environments that must be kept equivalent.
