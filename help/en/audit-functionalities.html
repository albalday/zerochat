Review 2: Features

ZeroChat 9.11.0 as the single frontend for local models. Updated on 24 October 2026.

1. Goal and method

The project's goal is for ZeroChat to be the single frontend for local models served separately through OpenAI-compatible APIs (vLLM, llama.cpp, LM Studio, SGLang) or Ollama. This review goes through the capabilities of version 9.11.0 (commit 170ee03) in the code, not in the documentation.

The most relevant additions since 9.2.3 are unattended runs (zerochat --prompt), configuration profiles with their MCP services and browser, Playwright MCP with its own engines or the user's browser, the diff viewer, live local server state with automatic reconnection, and remote connection with sign-in through the system account.

Each capability shows what protects it: [test] an automated test or [reading] code review.

3. Good practices with a local model server

AspectRecommendationBenefit in ZeroChat
Context capacityPublish the real context (meta.n_ctx in llama.cpp, max_model_len in vLLM).Compaction thresholds are computed on the real limit, not an assumed one.
ReasoningTurn on the server's reasoning parser.Reasoning goes to its own block and is forwarded between steps without mixing into the answer.
Tool callsTurn on the server's tool template (for example, --jinja).Structured calls; without it, ZeroChat extracts <tool_call> blocks from the text.
StreamingStreamed responses.Token-by-token text and immediate cancellation.
Remote accessSSH tunnel or HTTPS reverse proxy, never a public --host.The server keeps listening only on its own computer and requires sign-in.

4. Consistency with the help

The help was checked against the code:

  • Tools and agent: the 12 built-in tools, the agent with no step cap and subagents.
  • Local server and MCP: startup, connection, commands, external services and permissions.
  • Model browsing, profiles and unattended runs: they match the 9.11.0 options, without --print-url.
  • SSH tunnel from Android and reverse proxy: Settings › Connection and sign-in with the system account.
  • Composer and documents and reasoning and telemetry.

test_help_pages.js checks that every page has its linked translation, the 9.x version series, a unique title and description, and an up-to-date sitemap.

5. Limits

  • Single user: one system account, the one running zerochat; no roles.
  • Data in the browser: conversations, profiles and RAG live in IndexedDB and localStorage; exporting them is advisable.
  • Shared origin on GitHub Pages, an accepted risk.
  • Lexical RAG, without vector similarity.
  • Browsers: Chromium and Firefox; WebKit (Safari and every browser on iPhone and iPad) is not supported.
  • Windows: it works, but its own code paths are not tested automatically.
  • Web privacy: with a local LLM the chat stays on the computer, but the web tools query external services.

6. Verdict

A mature frontend for local models, now also for a remote server. ZeroChat 9.11.0 covers daily technical work with a local model: an agent with the computer's tools, documents and PDF, browsing with Playwright, profiles that prepare each environment, and unattended runs from the terminal. The unified remote connection, by tunnel or reverse proxy, lets you use it from a phone or another computer without exposing the local server.
