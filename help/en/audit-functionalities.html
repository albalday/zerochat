Audit 2: Functionalities and AI Testbed

What ZeroChat offers an AI practitioner for experimentation, and what it does not.

1. Goal

Evaluate ZeroChat 8.12.4 as a personal testbed to understand a language-model client, experiment with agents, tools and MCP, and observe inference, reasoning and context. Personal and self-training use, not professional use. Every capability cited was checked in the code.

2. Capabilities by area

ReasoningHighReasoning separated while streaming. Levels none, minimal, low, medium, high, xhigh and on.Reasoning tokens are collected but not shown in telemetry.

3. Consistency with the help

Checked by sampling, without comparing every sentence of every page:

  • RAG: states that search is lexical, without embeddings, and may miss synonyms or translations. Matches the code.
  • Infrastructure: states Safari incompatibility and that macOS requires Chrome; Linux, Windows 10/11 and Android with Termux environments.
  • Tools and agent: describes DuckDuckGo, Jina Reader, direct connection and AllOrigins.
  • Reasoning and telemetry: describes compaction at 70 %.
  • Learning: presents ZeroChat as a personal learning project.

In the points reviewed, the help is consistent with the code and does not promise capabilities that do not exist.

4. Use cases

Testing your own MCP server

Register it (local stdio or external HTTP), view its tools and test the agent's behavior under different policies. Tool cards show the arguments and results. It does not show raw JSON-RPC messages; for that you need the MCP Inspector or server-side logging.

Comparing reasoning across models

Adjust the intensity and see reasoning separately from the answer. The reasoning-token count is not shown in the interface: check it in the raw JSON in the debug panel.

Intercepting and modifying requests

With Debug messages, each request pauses before sending and shows the exact JSON, which can be edited, validated and sent, or cancelled.

Local inference with WebGPU

WebLLM in a dedicated Web Worker, without a backend. The catalog recommends models that handle tools better (Qwen3/3.5, Hermes). The engine is downloaded from jsDelivr and models take from hundreds of MB to several GB.

Studying the architecture

Modular UMD JavaScript without a bundler or framework: SSE parsing, provider normalization, cancellation with AbortController and process-group termination in Python.

5. Limits

  • Single user: no concurrent sessions or roles.
  • Data in the browser: clearing site data without exporting loses it.
  • Shared origin on GitHub Pages (accepted risk).
  • Lexical RAG: no semantic search.
  • Browsers: Chromium and Firefox; Safari/WebKit not supported. WebLLM requires WebGPU.
  • Conditional privacy: messages reach the chosen remote provider and web tools use third-party services.

6. Verdict

Well suited as a personal AI lab. It lets you see and modify the request, streaming, reasoning, context and agent orchestration, and the help honestly describes its main limits.

Proposed improvements: show reasoning tokens in telemetry, log MCP JSON-RPC traffic in the debug panel and add a guide of reproducible experiments.
