Profiles & AI Providers

Learn how to connect ZeroChat with any language model, running either on your machine or in the cloud.

1. Connection Profile Management

ZeroChat lets you define multiple connection profiles. A profile encapsulates the API protocol type, server endpoint URL, authentication key (optional for local servers), and selected model name.

To manage profiles, click the active profile name button located in the bottom-right corner of the composer and choose "Edit profiles", or open the settings dialog from the sidebar.

Instant switching: You can switch models or providers mid-conversation without losing context. Simply open the profile dropdown and select another one.

3. Server Inspection (Query Button) & Validation

When creating or editing a profile, ZeroChat provides a Query button next to the URL input. This inspects the server before saving:

  • Model discovery: Fetches the available models catalog and populates the dropdown automatically.
  • Capability inspection: Verifies if the model supports vision, function calling (tools), native reasoning, and advertised context capacity.
  • Save protection: For remote APIs or local HTTP endpoints, ZeroChat requires a successful Query before saving to ensure the connection works properly.
Fast save on WebLLM: When selecting an already downloaded WebLLM model from local cache, the Query button is optional, allowing you to save the profile immediately.

4. Special Configuration for Ollama (CORS)

When connecting to Ollama, browsers will block requests due to CORS (Cross-Origin Resource Sharing) unless Ollama is started with cross-origin access enabled: 

# On Linux / macOS (terminal)
OLLAMA_ORIGINS="*" ollama serve

# On Windows (PowerShell)
$env:OLLAMA_ORIGINS="*"
ollama serve

If running Ollama as a systemd service on Linux, add Environment="OLLAMA_ORIGINS=*" under the [Service] section.

5. The Built-in "Mirror" Profile

ZeroChat includes a read-only Mirror (Espejo) profile. It is ideal for UI testing and troubleshooting:

  • Makes zero network calls and needs no local server running.
  • Returns an immediate formatted preview of the normalized OpenAI-compatible payload.
  • Serves as a reliable fallback whenever an active profile is deleted or inaccessible.
