Agent Mode & Built-in Tools

Enabling, running and understanding the limits of tools available to the model.

1. How the agent works

With a model that supports tools, ZeroChat can alternate model requests and executions: the model requests a tool, receives its result and decides the next step. A tool may run in the browser, on the local server or in an MCP service.

Enable the tools you need in Settings and review their permissions. The agent turn limit is configurable from 5 to 200 and defaults to 40. It limits iterations, without guaranteeing completion or setting a maximum cost. You can stop generation; completed actions are not undone.

In Settings → Agent, the turn limit appears in an open section and each tool uses a soft background without nested frames. Descriptions adapt to the available width and each switch stays beside its tool.

Native and MCP tools share collapsible cards grouped by execution. On mobile, the status appears below the name. Charts remain open outside the groups; MCP screenshots can keep their card open to display the image.

Automatic collapsing affects only the tool that has just finished: groups and previous executions you opened stay open.

2. Built-in tools

ToolUse and limits
execute_javascriptCalculations and transformations in an isolated browser environment.
search_webSearch through DuckDuckGo or SearXNG. Quotas, blocks or service changes can cause failures.
fetch_web_pageRetrieves text from public pages; it does not replace a signed-in browser.
download_pdfDownloads a PDF and extracts readable text, subject to parser limitations.
render_chartDisplays data in SVG charts; it does not validate data or calculations.
list_documents, search_knowledge_base, read_knowledge_chunk, read_knowledge_imageQuery active RAG branches.
agent_checkpointRecords findings and the next step.
update_planDisplays tasks and their status as declared by the model.
finish_taskSignals completion with a summary; it does not independently check the result.

Web tools send queries and URLs to third-party services. search_web queries DuckDuckGo, first through Jina Reader (r.jina.ai) and then directly, or the configured SearXNG instance. fetch_web_page and download_pdf try Jina Reader first and, if it fails, a direct connection and the AllOrigins proxy (api.allorigins.win). Local network URLs are always requested directly. Do not assume a connection without intermediaries or send these tools private URLs or credentials.

File, terminal and browser automation tools need the local server. Their calls include authorization and a temporary single-use signature; this does not protect against a compromised interface with session access.

3. Running JavaScript

execute_javascript runs code using an iframe with an isolated origin, network restrictions and a Web Worker. Time and output limits apply; the aim is to perform calculations without giving code direct access to chat or disk.

Enable it when you need this processing and can review what it does. Isolation does not guarantee correct results or eliminate every resource risk. System commands use separate tools on the local server.

4. Tool cards

Consecutive calls are grouped in one “Tool calls” line. While running it shows the active calls; when finished it is collapsed and can be expanded to inspect the cards with status, arguments and results. Saved cards are restored when opening history.

Review paths, commands and web destinations before authorizing. A successful execution status means the call completed, not that the user's task was solved correctly. Errors or cancellation can leave partial effects: check affected files or services before repeating.
