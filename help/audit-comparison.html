Revisión 3: Comparativa

¿Qué frontend conviene para un LLM local servido aparte?

Vigencia y método: los datos de ZeroChat se han comprobado en su código (9.1.0, commit a0393c3); los del resto proceden de su documentación pública, consultada el 4 y el 12 de octubre de 2026. Lo que no consta en esa documentación se indica como «no consta», no como «no». No se han medido memoria ni rendimiento.

1. Por qué cambia la comparativa

La auditoría de la 8.12.4 comparaba ZeroChat con clientes multiproveedor. El objetivo actual es otro: un único frontend para modelos locales, servidos por su propio motor; el modelo cambia según la tarea. Por eso aquí se comparan las interfaces que se usan habitualmente delante de un servidor local, y se descartan las que solo trabajan con un proveedor remoto.

3. Análisis

Frente a la interfaz de llama.cpp

Es la opción mínima: viene con el servidor y no hay nada más que instalar. Sirve para conversar y probar el modelo, pero la documentación consultada no menciona MCP ni acceso al equipo. ZeroChat añade agente, herramientas locales, permisos, modo proyecto y depuración sobre el mismo endpoint.

Frente a LM Studio

LM Studio une motor e interfaz y, desde la versión 0.3.17, actúa como cliente MCP con confirmación de cada llamada y argumentos editables. Es la alternativa más cercana para un solo usuario. ZeroChat no ejecuta el modelo: se sitúa delante de cualquier servidor (vLLM, SGLang, llama.cpp) y añade reglas de permisos por directorio y comando, subagentes y el interceptor de peticiones.

Frente a Open WebUI

Es un servidor con base de datos pensado para varios usuarios, con RAG vectorial y MCP nativo. Gana en administración, roles y búsqueda semántica. ZeroChat no necesita servidor propio para chatear, arranca sin Docker y funciona en Android con Termux, aunque allí sin automatización de navegador.

Frente a Jan

Aplicación de escritorio que ejecuta modelos GGUF con llama.cpp y admite MCP. Interesa si se quiere que la misma aplicación cargue el modelo. Para un modelo de 27B servido con vLLM o SGLang, aporta menos que un cliente que se limita a hablar con el endpoint.

4. Diferenciadores de ZeroChat para este uso

  • Independencia del motor: el mismo frontend sirve para vLLM, SGLang, llama.cpp, LM Studio u Ollama.
  • Razonamiento reenviado entre pasos del agente cuando el servidor lo separa en su campo.
  • <tool_call> en texto como respaldo cuando el servidor no analiza las llamadas.
  • Permisos con reglas de directorio y comando y firma de un solo uso en cada llamada al backend.
  • Interceptor editable para ver exactamente qué recibe el modelo local.

Y sus desventajas: sin RAG semántico, sin multiusuario y con la carga de mantener el proyecto quien lo usa.

5. Cuándo elegir cada uno

  • ZeroChat: un solo usuario, modelo servido aparte, agente con acceso controlado al equipo y necesidad de ver cada petición.
  • LM Studio: una sola aplicación que cargue el modelo y ofrezca MCP con confirmación.
  • Interfaz de llama.cpp: probar el modelo sin instalar nada más.
  • Open WebUI: varios usuarios, roles o RAG vectorial.
  • Jan: aplicación de escritorio que ejecute GGUF localmente.

Conclusión: MCP ya no distingue a nadie. Lo que justifica ZeroChat para el objetivo actual es la independencia del motor, las reglas de permisos y la transparencia de la petición.
