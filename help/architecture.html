Distribución de funciones entre el navegador y el servidor local.

Niveles de uso

ZeroChat utiliza el mismo motor agéntico en cinco niveles progresivos: puedes empezar con el navegador sin instalar nada y añadir el servidor local o la ejecución desatendida solo cuando los necesites.

NivelQué necesitasQué permite
1. Chat simple (solo frontend)Navegador (o PWA)Chat, perfiles, adjuntos, RAG local en navegador, JavaScript en sandbox, búsqueda/lectura web y WebLLM (WebGPU). Sin acceso a archivos del equipo.
2. Chat con backend localzerochat (Python)Acceso controlado por proyecto a ficheros y comandos (reglas RWX), desarrollo con modo proyecto, servicios MCP, navegador del modelo y sincronización en SQLite.
3. Ejecución por CLIzerochat + Node.js ≥ 22.13Peticiones desde shell o cron con --prompt y --conversation sin abrir navegador, con la respuesta directa en stdout.
4. Segundo plano en servidorzerochat + Node.js ≥ 22.13Turnos lanzados desde la interfaz como procesos independientes: puedes cerrar el cliente y volver luego para ver el avance o responder un needs_input.
5. Orquestaciones de agenteszerochat + Node.js ≥ 22.13Agentes desatendidos con --run-file, agentes controladores que lanzan y supervisan workers (launch_agent, check_agents, stop_agent, prune_agents) y consola de supervisión humana (pestaña Agentes).

Instalar y arrancar el servidor local → · Herramientas y MCP → · CLI y agentes desatendidos →

Si el navegador lo permite, puedes instalar la web como PWA. La caché no garantiza que todas las funciones funcionen sin conexión.

Entornos probados: Linux (x86_64 y ARM), Windows 10/11 (PowerShell y lanzador py -m zerochat) y Android (Termux con paquete python). En Termux no es posible usar Playwright actualmente, así que browser_action y Playwright MCP no están disponibles.
Compatibilidad de navegadores: ZeroChat no es compatible con Safari debido a restricciones de red privada local (Private Network Access) y almacenamiento web. En macOS debería funcionar con Firefox o con navegadores basados en Chromium, pero no se ha probado.

Dónde se guardan los datos

En el navegador

Sin servidor, conversaciones, perfiles, adjuntos y RAG viven en el navegador (ligados al origen web y perfil del navegador). Al conectar el servidor local, perfiles y conversaciones se sincronizan con SQLite para continuar desde otro navegador o dispositivo. Exporta copias antes de limpiar los datos.

Las conversaciones no están cifradas como una bóveda. Consulta cómo se guardan las claves API y sus límites en Perfiles.

En el equipo, con el servidor local

~/zerochat/
├── storage/     Base de datos SQLite (conversaciones, perfiles, permisos, secretos y runs)
├── config/      Token diario de sesión
├── general/     Carpeta por defecto para chats sin proyecto
├── services/    Servicios MCP gestionados y sus dependencias
├── cache/       Caché de módulos del runner de Node.js
└── .venv/       Entorno aislado para servicios MCP en Python

PyPI y el script descargado utilizan la misma carpeta. Borrarla restablece todo el estado del backend (incluida la base de datos y los servicios gestionados), sin tocar el ejecutable, la copia del navegador ni archivos de tus proyectos.

Conexiones y privacidad

La interfaz publicada está en GitHub Pages. El servidor local escucha por defecto en 127.0.0.1:6388 y abre un enlace autenticado. No compartas la URL de arranque mientras contenga el token; la interfaz lo retira y lo guarda en una cookie. Sin ese enlace (otro equipo, un túnel SSH o un proxy inverso), la conexión se configura en el panel de Conexión (el icono del enchufe, junto a la rueda de configuración de la barra lateral) y la página pide el usuario y la contraseña de la cuenta que ejecuta el servidor para obtener el token del día.

Los proveedores remotos reciben los mensajes, adjuntos y resultados de herramientas incluidos en sus peticiones. Las herramientas web no usan proxies ni intermediarios públicos. Los modelos y dependencias también necesitan descargas.

Las librerías de terceros (Orama para la búsqueda; mammoth y fflate para documentos ofimáticos) van incluidas en la propia web con versiones fijas, sin CDN. Las de documentos se descargan del mismo sitio la primera vez que se usan y quedan en caché para trabajar sin conexión. Sus licencias figuran en THIRD_PARTY_NOTICES.md.

WebLLM ejecuta la inferencia localmente; las herramientas de red siguen enviando datos. Guardar el historial localmente no hace privadas todas las operaciones. El panel de depuración permite revisar las peticiones; su contexto puede diferir del historial visible por límites de tokens o selección RAG.

Actualizaciones

Las actualizaciones de la web llegan desde GitHub Pages. Los parches de una misma serie, como 9.1.x, son compatibles con el backend 9.1 y no requieren reinstalarlo. Cuando hay una versión nueva de la web, ZeroChat ofrece Recargar ahora o Más tarde; recargar aplica la versión sin perder el historial guardado. Con Más tarde sigues con la versión actual completa hasta que aceptes el aviso o cierres todas las pestañas de ZeroChat.

Una nueva serie major.minor puede requerir actualizar el backend. Sigue el aviso de la terminal para tu forma de instalación; el ejecutable no se actualiza automáticamente. Pulsa i cuando la terminal ofrezca información.

Desarrollo local

Dentro del repositorio, python3 zerochat.py sirve http://127.0.0.1:6388/zerochat.html. Su almacenamiento del navegador es distinto del de GitHub Pages. La interfaz carga js/ y css/; copiar solo el HTML no basta.

python3 zerochat.py --test comprueba las herramientas locales. Para la suite de pruebas del proyecto, consulta tests/README.md en el repositorio.
