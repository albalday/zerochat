Arquitectura y Portabilidad

Distribución de funciones entre el navegador y el servidor local.

1. Aplicación web y backend local

La interfaz se sirve como archivos estáticos: zerochat.html carga módulos de js/ y css/. No es un único HTML autónomo. El navegador ejecuta la interfaz, conserva datos y realiza las peticiones al proveedor elegido.

El backend opcional es el ejecutable zerochat de PyPI o el script zerochat.py. Añade herramientas del equipo y gestión de servicios MCP. No es necesario para el chat con un proveedor accesible desde el navegador.

2. Modos de arranque

A. Web

Abre la interfaz de GitHub Pages por HTTPS. Incluye perfiles, chat, adjuntos, RAG, herramientas ejecutadas en el navegador y WebLLM si el dispositivo admite WebGPU. Las APIs remotas requieren red, credenciales cuando proceda y acceso permitido desde el navegador.

La instalación como PWA depende del navegador y se hace desde sus opciones. ZeroChat no muestra un botón ni un aviso de instalación. El Service Worker puede reutilizar recursos en caché, sin garantizar que todas las funciones estén disponibles sin conexión.

B. Backend local

Añade lectura y escritura de archivos, búsqueda, comandos, diagnósticos, automatización de navegador y servicios MCP. Requiere Python y los requisitos propios de cada herramienta. La disponibilidad debe comprobarse en el sistema operativo concreto.

3. Web publicada y desarrollo local

Fuera del repositorio, el ejecutable abre GitHub Pages y escucha por defecto en 127.0.0.1:6388. La interfaz recibe el token de arranque, lo retira de la dirección y lo conserva en una cookie del origen web. No compartas esa URL antes de que se retire el token.

Dentro del repositorio, python3 zerochat.py detecta los archivos de desarrollo y sirve http://127.0.0.1:6388/zerochat.html. Este origen tiene almacenamiento distinto de GitHub Pages.

python3 zerochat.py --test ejecuta una autocomprobación de herramientas. npm test ejecuta la suite del proyecto y npm run test:browser las pruebas de navegador. Una autocomprobación no valida todos los proveedores ni todas las plataformas.

4. Distribución y actualizaciones

pip install zerochat instala el ejecutable Python; la descarga directa proporciona zerochat.py. La interfaz se carga por separado desde GitHub Pages. Ambos modos preparan este estado local:

~/zerochat/
├── .venv/       Dependencias de MCP Python
├── config/      Token y configuración
└── services/    Servicios MCP

Borrar esta carpeta elimina ese estado, no el ejecutable instalado, el historial del navegador ni archivos modificados fuera de ella.

Al iniciar fuera del repositorio, el ejecutable consulta la versión de la interfaz publicada en GitHub Pages y la versión estática de zerochat.py publicada en GitHub. La terminal permite consultar ambas con i. La compatibilidad se identifica con major.minor: por ejemplo, la interfaz 8.0.x corresponde al backend 8.0. Los parches web no requieren reinstalarlo. Para una nueva serie, el aviso indica el comando de actualización de PyPI con su intérprete o la descarga del script. No se actualiza automáticamente.

5. Almacenamiento y privacidad

Qué se guarda

IndexedDB conserva conversaciones, perfiles, adjuntos y RAG. Otras preferencias y material de desbloqueo usan almacenamiento del navegador; los modelos utilizan caché. Los datos pertenecen al origen, navegador y perfil usados. No hay sincronización automática ni garantía de conservación si el navegador los elimina.

Las conversaciones no están cifradas como una bóveda. Las claves API tienen cifrado local con limitaciones que se explican en Perfiles. Exporta copias de lo que necesites conservar antes de limpiar datos.

Qué sale del equipo

Los proveedores remotos reciben los mensajes, adjuntos y resultados de herramientas que se incorporan a sus peticiones. Las búsquedas y lecturas web pueden pasar por servicios externos como Jina Reader o AllOrigins; las dependencias y modelos también pueden descargarse de servidores externos.

WebLLM realiza la inferencia local, pero usar herramientas de red sigue generando comunicaciones. Revisa proveedor y herramientas antes de enviar contenido sensible. Alojar el historial localmente no equivale a privacidad absoluta.

6. Estado de la aplicación

ChatState coordina configuración, sesiones, mensajes, generación, agente, telemetría, interfaz y permisos. Los módulos utilizan mutadores de dominio para mantener los cambios sincronizados.

Es una decisión interna de arquitectura. No añade sincronización entre dispositivos ni convierte la sesión del navegador en un entorno aislado para cada herramienta del backend.

7. Reglas compartidas de conversación

La gestión de turnos, los componentes de mensajes y la presentación de errores se comparten entre conversaciones nuevas y restauradas. Las herramientas guardadas conservan sus resultados en el historial.

El historial visible y el contexto enviado al proveedor pueden diferir por límites de tokens, adaptación del proveedor o selección de fragmentos RAG. Utiliza el panel de depuración para revisar una petición concreta.
