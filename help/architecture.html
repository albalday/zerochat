Arquitectura y Portabilidad

Descubre cómo funciona ZeroChat como aplicación web autónoma, independiente de servidor y 100% portable.

1. El Concepto de Archivo Único Autónomo

ZeroChat está diseñado bajo una premisa fundamental: máxima portabilidad sin sacrificar capacidades avanzadas.

El producto final se compila en un único archivo distribuible denominado zerochat.html. Este archivo contiene todo el código HTML, los estilos CSS minificados y comprimidos con Gzip L9 en Base64, los módulos JavaScript de la aplicación y las bibliotecas cliente esenciales (incluyendo el motor de búsqueda Orama).

Al abrir zerochat.html, un bootstrap ultraligero descomprime en milisegundos los componentes utilizando la API nativa DecompressionStream del navegador, permitiendo que la aplicación arranque de inmediato.

Ventaja clave: Puedes guardar zerochat.html en una memoria USB, en tu escritorio, enviártelo por correo o WhatsApp y ejecutarlo en cualquier navegador moderno sin necesidad de instalar Node.js, Python, Docker ni dependencias del sistema operativo.

2. Ejecución con Protocolo file:// vs Servidor Web

ZeroChat está adaptado para funcionar con total normalidad bajo dos modos de despliegue:

  • Protocolo local file://: Haciendo doble clic directamente sobre el archivo en tu explorador de archivos. No requiere levantar ningún servidor local. Las peticiones a APIs remotas o a servidores locales (como Ollama o LM Studio) se realizan mediante fetch directo desde el navegador (con soporte de CORS habilitado en el proveedor).
  • Servidor estático o GitHub Pages (HTTP/HTTPS): Hospedado en cualquier servidor web básico (Nginx, Apache, Caddy, Vercel o GitHub Pages). En este modo se cuenta además con acceso completo a APIs modernas como navigator.storage.persist() y facilidades adicionales de seguridad de contexto seguro.
Nota sobre restricciones en file://: Algunos navegadores limitan ciertas capacidades en el origen file:// (como la descarga automática del propio bundle o ciertos accesos a Service Workers). Para la máxima potencia en modelos locales WebGPU o RAG pesado, se recomienda un origen HTTP local o HTTPS.

3. Almacenamiento Local y Privacidad de Datos

La arquitectura de datos de ZeroChat sigue el principio de soberanía del usuario. La aplicación nunca envía historiales de conversación, credenciales ni documentos a ningún servidor centralizado de telemetría.

Capas de almacenamiento en el cliente:

  • IndexedDB (ZeroChatDB): Base de datos estructurada en el navegador donde se guardan las sesiones de chat, los mensajes, metadatos, configuraciones de perfiles de usuario y las ramas del motor RAG.
  • Almacenamiento aislado de adjuntos: Las imágenes Base64 y los documentos pesados se aíslan en almacenes específicos de IndexedDB para que el árbol de mensajes permanezca rápido, ligero y fluido.
  • Cache Storage API: Utilizada por el motor WebLLM para almacenar de forma persistente los pesos y parámetros de modelos locales de lenguaje descargados.
  • LocalStorage / Cookies de sesión (ChatStorage): Gestiona estados efímeros, la clave de Gemini Free Tier (si se define localmente) y preferencias de interfaz (como el tema oscuro o claro activo).

4. El Estado Canónico (ChatState)

Para evitar fugas de memoria o desincronizaciones entre componentes, ZeroChat utiliza un almacén de estado único y centralizado denominado ChatState.

Todo cambio en el ciclo de vida de la aplicación (cambio de sesión, inserción de un mensaje por streaming, progreso de inferencia o invocación de herramientas) se realiza mediante mutadores atómicos de dominio (como appendMessage, replaceMessages o saveSessionMetadata). De este modo, la interfaz se actualiza de manera reactiva y consistente en todo momento.
