Proyecto y aprendizaje

Dos líneas de autoaprendizaje: construir un cliente de IA y aprender a dirigir su desarrollo con agentes.

ZeroChat es un proyecto personal de autoaprendizaje del desarrollador. Su objetivo es comprender la tecnología de los clientes de chat y la ejecución agéntica, y experimentar con Codex y Antigravity sin editar nunca código a mano. El trabajo humano consiste en definir objetivos, discutir decisiones con el modelo y comprobar resultados; los agentes implementan los cambios.

1. Aprender la tecnología de un cliente de chat

El historial muestra un recorrido desde ChatCLI hasta un cliente con conocimiento local y herramientas:

  • Chat y proveedores: streaming SSE, razonamiento, visión y adaptación de APIs. La arquitectura de proveedores se separó en agosto de 2026 (9bd4b1d).
  • Datos y documentos: persistencia en IndexedDB, extracción de PDF y recuperación de conocimiento (RAG). Tras explorar almacenamiento en archivos, se unificó el motor con Orama y ZeroChatDB en septiembre (481c9c6).
  • Ejecución agéntica: bucles de herramientas, JavaScript aislado en Web Workers, MCP y permisos. La evolución llegó a un servidor local Python con herramientas de desarrollo y Playwright (219ed4a).
  • Inferencia y contexto: caché, límites de tokens y puntos de control para conversaciones largas; después, modelos dentro del navegador con WebLLM y WebGPU (6bd4b31, e20a70c).

2. Aprender a dirigir agentes de codificación

Al crecer la infraestructura —navegador, almacenamiento, proveedores, servidor MCP y bundle—, el aprendizaje también consiste en mantener el control del conjunto:

  • Planificar antes de ejecutar: concretar alcance, fases y criterios de aceptación. Git conserva el plan de WebLLM antes de su implementación y el diseño de partición de app.js antes de las extracciones (e122f9f, b404c4a).
  • Convertir decisiones en normas: documentar arquitectura, contratos y flujo Git para orientar al agente. Las reglas evolucionaron hacia AGENTS.md, estado centralizado en ChatState y responsabilidades separadas (cb06bc4, 66a1967).
  • Discutir y simplificar con el modelo: cuestionar propuestas, reutilizar módulos y retirar complejidad innecesaria. El historial recoge la unificación del runtime agéntico y la eliminación de código obsoleto (3d2a7e5, 02a7729).
  • Verificar cada avance: pruebas unitarias y de navegador, auditorías de seguridad y validación del bundle. También se aprende a mantener las pruebas: se añadieron comprobaciones de interfaz y después se eliminaron duplicados (aae43d2, de0ffd5).

El plan es continuar este ciclo: elegir una capacidad, acordar un diseño sencillo, encargar cambios acotados, revisar las pruebas y documentar lo aprendido.

Recorrido basado en el historial de Git hasta el 14 de septiembre de 2026. El compromiso de trabajar con Codex y Antigravity sin código manual quedó documentado en 65746ba. Los identificadores permiten localizar los hitos en el repositorio.
