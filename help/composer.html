Composer, Atajos y Archivos Adjuntos

Redactar mensajes, adjuntar archivos y revisar lo que se envía al proveedor.

1. Cuadro de entrada

El campo crece al escribir. La barra inferior reúne adjuntos, razonamiento, selección RAG y contexto; las herramientas y MCP se configuran desde Ajustes.

Pulsa Enviar para iniciar la respuesta. Durante la generación, el botón permite detenerla. Detener solicita la cancelación: no deshace una edición, un comando o una acción web que ya se haya ejecutado.

2. Atajos de teclado

  • Enter: enviar el mensaje desde el cuadro de texto.
  • Shift + Enter: insertar un salto de línea.
  • Escape: cerrar los diálogos o menús que admiten este atajo.
  • ↑ / ↓: recorrer opciones del selector de perfiles.
  • Ctrl / Cmd + V: pegar texto; el pegado de imágenes depende del contenido y de los permisos del portapapeles.

3. Archivos adjuntos

Usa el clip, arrastra archivos al chat o pega una imagen. Revisa los adjuntos antes de enviar y elimina los que no quieras incluir con su botón de cierre.

  • Imágenes: requieren un modelo con visión; admitir un archivo no asegura que el proveedor acepte su formato o tamaño.
  • PDF: se extrae texto en el navegador. Los escaneos sin texto y los diseños complejos pueden dar resultados incompletos; no hay OCR general.
  • Documentos ofimáticos: Word (DOCX), Excel (XLSX), PowerPoint (PPTX) y OpenDocument (ODT, ODS, ODP) se convierten en el navegador a texto con títulos, listas y tablas; las presentaciones se marcan por diapositiva y cada hoja de cálculo se envía como tabla de hasta 500 filas. Hasta 4 imágenes por documento se envían al modelo si admite visión. Las macros no se ejecutan y los formatos antiguos (DOC, XLS, PPT) no se admiten: guárdalos en el formato actual.
  • Texto y código: admite, entre otros, TXT, Markdown, JSON, JavaScript, Python, HTML y CSS.
  • CSV y TSV: se envían como contenido textual que el modelo puede analizar; comprueba delimitadores, unidades y resultados.

La primera vez que adjuntas un documento ofimático se descarga su librería de lectura desde la propia web de ZeroChat y queda en caché; sin conexión, solo funciona si ya se descargó antes.

El contenido adjunto se envía al proveedor con el mensaje y consume contexto. Para consultar partes de varios documentos, utiliza la base RAG.

4. Presentación de mensajes, tablas y documentos

Las respuestas admiten Markdown, tablas con desplazamiento horizontal y acciones de copia y descarga a CSV (RFC 4180), bloques de código con copia y vista previa, y notación matemática normalizada. Los bloques de código HTML o SVG y las tarjetas de herramientas que escriben archivos (como write_file) incluyen un botón de Vista previa que abre el documento o marcado directamente en una nueva pestaña aislada. Las imágenes mostradas en la conversación (adjuntos, páginas web, RAG o capturas de herramientas) pueden pulsarse para abrirlas a tamaño completo en una pestaña nueva. El razonamiento que expone el proveedor aparece en bloques plegables; las llamadas a herramientas tienen tarjetas con argumentos, resultados y estado.

El formato no valida el contenido: revisa código, cálculos y enlaces antes de utilizarlos.
