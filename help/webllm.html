Configuración de WebLLM y WebGPU

Preparar un modelo en el navegador y reconocer los límites de WebGPU.

Qué hace WebLLM

WebLLM ejecuta un modelo dentro del navegador usando WebGPU. La inferencia no necesita una API remota, pero la primera preparación descarga el runtime y los pesos. Las herramientas web o MCP pueden seguir comunicándose con servicios externos.

La ejecución sin conexión depende de que estén disponibles todos los recursos de la aplicación y del modelo en caché. No se garantiza con solo haber abierto una vez la página. Consulta la guía de WebLLM.

Requisitos de hardware

Necesitas un navegador con WebGPU operativo, un adaptador gráfico compatible y memoria suficiente. El catálogo muestra una estimación de memoria por modelo; el contexto y el procesamiento del prompt añaden consumo.

Empieza con un modelo pequeño y una ventana moderada. Tener WebGPU disponible no garantiza que un modelo concreto quepa en la GPU o funcione con sus controladores.

Configuración por Navegador

Chrome, Edge y Chromium

Usa una versión actualizada, revisa la aceleración gráfica en los ajustes del navegador y comprueba el estado de WebGPU en su página de diagnóstico, por ejemplo chrome://gpu.

No es necesario activar flags experimentales como paso habitual. Forzar opciones que omiten comprobaciones del controlador puede introducir fallos y no soluciona la falta de memoria o de soporte del dispositivo.

Firefox

La disponibilidad depende de la versión, sistema operativo, GPU y controladores. Revisa about:support y comprueba si ZeroChat detecta WebGPU.

No cambies preferencias avanzadas ni ignores bloqueos de controladores como requisito general. Si el entorno no ofrece WebGPU utilizable, utiliza otro entorno compatible o un perfil con servidor de inferencia.

Usar WebLLM en ZeroChat

  1. Crea o edita un perfil y selecciona WebLLM.
  2. Pulsa Query para abrir el catálogo. Los modelos completados aparecen primero.
  3. Descarga un modelo y espera a que termine su preparación. Una descarga incompleta no cuenta como modelo disponible.
  4. Selecciona el modelo y guarda el perfil. Si ya estaba descargado, no hace falta repetir Query para guardarlo.

La preparación inicial puede tardar y ocupar varios gigabytes. La caché pertenece al navegador y origen usados; otro navegador puede necesitar descargarlo de nuevo.

Parámetros de rendimiento

El engranaje del perfil WebLLM permite ajustar context_window_size (ventana de contexto) y prefill_chunk_size (bloque de procesamiento del prompt).

Por defecto del modelo conserva su configuración. Aumentar el contexto consume más memoria. Cambiar el prefill puede afectar velocidad y memoria, sin asegurar una mejora. Si falla la preparación, vuelve a los valores predeterminados o prueba un modelo menor.

Restablecer ajustes y liberar espacio

1. Chrome, Edge y Chromium

Si modificaste un flag, restablece esa opción a Default y reinicia. Evita restablecer todas las opciones del navegador si solo cambiaste una.

2. Firefox

Si modificaste una preferencia de WebGPU, usa su control de restablecimiento en about:config. El valor predeterminado depende de la versión: no lo sustituyas por un valor fijo tomado de una guía antigua.

3. Modelos descargados

Utiliza la acción de eliminación del catálogo para borrar un modelo. Para reiniciar todo el almacenamiento, Configuración → Borrar todo elimina datos del origen actual, incluidos conversaciones, perfiles, RAG, adjuntos y modelos. Exporta lo que quieras conservar y cierra las otras pestañas antes de confirmar.

El borrado no elimina archivos descargados al disco, cookies HttpOnly ni la caché HTTP interna del navegador. Si has usado varios orígenes, sus datos son independientes.

Problemas frecuentes

  • WebGPU no disponible: revisa navegador, contexto seguro (HTTPS o localhost), controladores y aceleración gráfica.
  • Falta de memoria: cierra otras cargas de GPU, reduce contexto o selecciona un modelo menor.
  • Error de descarga o preparación: lee el error completo de la fila del modelo, comprueba red y espacio y vuelve a intentarlo.
  • Caché ausente: la navegación privada, la limpieza del sitio o las cuotas del navegador pueden eliminar recursos. La caché no es una copia permanente garantizada.

La compatibilidad debe comprobarse en el dispositivo concreto. Un modelo puede conversar y aun así no admitir visión, herramientas o los ajustes de razonamiento de otro proveedor.
