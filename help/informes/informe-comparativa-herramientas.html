1. Conclusión

ZeroChat mantiene un espacio defendible como cliente web de experimentación personal con backend opcional y observabilidad de las peticiones. Chat multiproveedor, RAG y también MCP son ya habituales en las alternativas: Msty Studio, Open WebUI y LM Studio documentan ahora soporte MCP propio, por lo que MCP ha dejado de ser un rasgo diferenciador por sí solo.

Lo que sigue siendo distintivo es la combinación de acceso web directo, modo Espejo, inspector y telemetría, junto a un backend local que instala y arranca servidores MCP stdio y puentes remotos con OAuth sin configurar archivos a mano. Esa ventaja solo se sostiene si los permisos de las herramientas locales son fiables; hoy no lo son (T01 y T02 del informe técnico).

2. Método y selección

Se comparan las mismas siete alternativas que en la revisión anterior para mantener la continuidad: Cherry Studio y Msty Studio como clientes personales; Open WebUI y LibreChat como aplicaciones de mayor amplitud; AnythingLLM para trabajo documental; LM Studio para modelos locales; Aider para programación en repositorios.

Las afirmaciones sobre terceros proceden de su documentación oficial consultada en la fecha indicada; se han revisado expresamente las páginas de MCP de Msty Studio, Open WebUI y LM Studio. No se instalaron ni midieron. No se comparan precios, planes ni calidad del código ajeno. Cuando una prestación no se verifica, se indica en lugar de afirmar su ausencia.

5. Dónde aporta valor ZeroChat

Observación de la petición y diagnóstico

Modo Espejo, inspector, consulta de modelo y telemetría siguen alineados con probar sistemas. No se afirma que ningún competidor carezca de inspección; la diferencia propuesta es la prioridad que ZeroChat da a ese recorrido.

Aplicación web con infraestructura opcional

Iniciar una prueba no requiere un servidor propio; las herramientas del equipo se añaden con zerochat. La simplicidad debe juzgarse en el caso completo: MCP gestionados y navegador requieren Node.js y la inferencia local un motor o WebGPU.

MCP gestionado desde la web

Servicios incluidos que se instalan solos, puente remoto con OAuth también en Android/Termux y una plantilla para que el agente cree servicios propios. Es la novedad competitiva más clara de 8.x, condicionada a resolver T03 (un arranque bloquea a los demás).

Conocimiento pequeño sin embeddings

El índice léxico local puede bastar para identificadores, errores y manuales cortos, sin un servicio adicional. No demuestra mejor recuperación que las alternativas vectoriales.

7. Posicionamiento y prioridades

Mensaje recomendado:

Banco de pruebas personal de IA: conecta modelos, inspecciona peticiones, consulta documentos pequeños y prueba herramientas y servicios MCP desde una interfaz web.

Evitar como promesas centrales «privacidad absoluta», «RAG semántico», «sustituto de un IDE» o un control de permisos que hoy no confina.

8. Cómo comprobar la ventaja propuesta

Ensayo futuro con la misma persona, equipo, modelo y tareas: ZeroChat frente a Cherry Studio y Msty Studio como clientes personales, LM Studio para prueba local, AnythingLLM para documentos y Aider para una modificación de código. Incluir una tarea MCP: conectar un servidor stdio y uno remoto con OAuth, y medir tiempo hasta la primera llamada correcta.

Medir tiempo hasta el primer resultado correcto, configuraciones manuales, claridad del error, recuperación tras fallo y mantenimiento tras un mes sin uso. Hasta ejecutar ese ensayo, la conclusión es de encaje estratégico, no de superioridad demostrada.

Síntesis: MCP ya es común en las alternativas; ZeroChat se diferencia por el acceso web, el modo Espejo, el inspector y los servicios MCP gestionados desde la web. Esa ventaja depende de corregir los permisos y los bloqueos detectados en la auditoría técnica.
