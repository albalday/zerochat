Auditoría funcional independiente

Funcionalidades implementadas y madurez

Inventario contrastado con el código y las pruebas de ZeroChat 7.6.0. Se distingue entre presencia en interfaz, implementación real, prueba automatizada y validación operativa externa.

Autor: OpenAI Codex (GPT-5), auditor técnico de softwareFecha: 22 de septiembre de 2026Fuente única: zerochat-master(5).zip

Resumen ejecutivo

La amplitud funcional es alta para un proyecto personal: chat multimodelo, agentes, herramientas, MCP, RAG, WebLLM, PWA, perfiles, telemetría, exportación y backend local conviven en un producto coherente. La madurez funcional global se estima en 3,7/5.

El núcleo de conversación, estado, persistencia y proveedores es lo más maduro. MCP y RAG son funcionales y diferenciadores, pero aún necesitan más pruebas de aceptación con servicios y documentos reales. WebLLM debe seguir etiquetado como experimental. Las funciones multiusuario, administración, sincronización y colaboración no están implementadas porque no forman parte de la orientación actual.

Escala utilizada

1 · Experimental

Existe una idea o camino técnico, sin garantías de uso estable.

2 · Funcional limitado

Opera en casos controlados; cobertura, UX o compatibilidad todavía restringidas.

3 · Beta utilizable

Flujo completo y pruebas relevantes; quedan límites conocidos o validación externa.

4 · Maduro personal

Uso diario razonable, manejo de errores y regresión consistente.

5 · Producción amplia

Operación endurecida, observabilidad, compatibilidad y soporte multiusuario/organizativo.

MCP: alcance real

El backend expone cuatro herramientas locales de propósito general y puede gestionar procesos MCP externos por stdio. El repositorio incorpora cuatro descriptores:

ServicioEstado en el repositorioMadurez estimada
Playwright MCPPaquete y versión fijados, instalación Chromium y opción headlessBeta
Memory MCPPaquete oficial fijado y archivo JSONL persistenteBeta
MCP-LSPPaquete fijado y arranque Node gestionadoBeta
Dummy MCPServidor mínimo incluido para probar infraestructuraPrueba controlada

No se observa soporte directo para configurar servidores MCP remotos arbitrarios mediante Streamable HTTP/OAuth. ZeroChat usa HTTP/SSE entre navegador y su host local, y stdio entre ese host y los servicios gestionados.

Defecto funcional concreto: la tool local list_directory anuncia el parámetro max_depth, pero el backend solo lista el primer nivel y no usa ese valor. Hasta corregirlo, debe describirse como listado simple, no como recorrido recursivo.

RAG e ingesta documental: qué hace y qué no

Sí implementado

  • Extracción PDF propia de texto, mapas CMap e imágenes incrustadas.
  • Indexación local y persistencia separada de metadatos, chunks e imágenes.
  • Búsqueda léxica tolerante con boost de título y diversificación.
  • Recuperación agentic: listar, buscar, leer fragmentos e inspeccionar imágenes.
  • Importación/exportación de corpus.

Parcial o dependiente

  • Los PDF complejos dependen de lo que el parser propio pueda interpretar.
  • Las imágenes solo aportan valor si el modelo elegido tiene visión.
  • El rendimiento y la cuota dependen de IndexedDB y memoria del navegador.
  • La búsqueda multilingüe depende de la rama/tokenizador configurado.

No implementado

  • OCR de páginas escaneadas.
  • Embeddings semánticos locales o remotos.
  • Re-ranking por cross-encoder.
  • Parseo nativo de DOCX, XLSX, PPTX o EPUB.
  • Conectores de fuentes empresariales.

Aspectos que no deben sobreprometerse

  • “Un único HTML”: la aplicación es estática y no necesita empaquetado, pero carga 14 CSS y 65 JS; no es un archivo autónomo.
  • “RAG vectorial”: el código actual usa búsqueda textual Orama; no se generan embeddings.
  • “Sandbox seguro”: el Worker JavaScript reduce superficie y bloquea APIs conocidas, pero el propio README reconoce que no es una VM ni aislamiento de sistema operativo.
  • “Claves seguras”: están cifradas con AES-GCM, pero una clave pública embebida permite recuperación a quien ejecute código en el mismo origen.
  • “Compatibilidad con proveedores”: los adaptadores y mocks están bien probados, pero cada proveedor puede cambiar APIs, CORS y semántica de tool calling.
  • “Soporte móvil completo”: la PWA es móvil; las tools locales, procesos MCP y automatización de navegador siguen siendo una experiencia principalmente de escritorio.

Preparación para enseñarlo a técnicos

La demostración más convincente sería un flujo corto y reproducible:

  1. Abrir el modo Espejo y enseñar el payload generado sin gastar API.
  2. Conectar un endpoint OpenAI-compatible local y mostrar streaming, razonamiento y métricas.
  3. Importar un PDF, activar una rama RAG y dejar que el agente busque y lea un chunk.
  4. Arrancar zerochat.py, mostrar el token eliminado de la URL y listar las tools locales.
  5. Ejecutar una tool con confirmación y enseñar su tarjeta/resultado.
  6. Cerrar con npm run test:all o con el resultado de CI, no con una promesa verbal de calidad.
Mensaje honesto y fuerte: “Es un laboratorio personal ya utilizable, construido para entender y controlar el recorrido completo entre navegador, LLM, contexto, RAG y herramientas locales; no pretende sustituir una plataforma empresarial”.
