7. Hallazgos pendientes y acciones concretas

F1 · Alta — Las autorizaciones no siempre componen sus restricciones

En js/tool-security.js, evaluateAuthorization devuelve command_directory_rules_allow antes de evaluar las restricciones guardadas del comando. Reproducción: una regla R:/tmp/zc-audit/** y un permiso limitado a allowedPrefixes: ['ls'] permiten cat /tmp/zc-audit/demo.txt. La evaluación aislada del prefijo pide aprobación; la evaluación combinada lo permite sin preguntar. AgentCore acepta ese resultado directamente.

Además, una regla relativa R:docs/** autoriza cat docs/demo.txt independientemente de cwd. No se resuelve la ruta real del sistema ni sus enlaces simbólicos en el cliente. Y zmcp_list_directory sin path evita la rama de reglas de carpetas y cae en allow_all, aunque el backend aplica por defecto ".".

Acción: normalizar argumentos por defecto antes de autorizar; evaluar conjuntamente permiso de herramienta, comando, directorio y cwd, respetando denegaciones. Para imponer una frontera real de carpetas, validar también rutas canónicas en el servidor. Esto no exige construir una sandbox completa: hay que declarar con precisión qué protege el control de interfaz.

F2 · Alta — Un modo de edición desconocido sobrescribe

En zerochat.py, validate_local_tool_arguments comprueba que mode sea texto, pero no su conjunto de valores. edit_file usa su rama else como escritura completa. Una llamada con mode: 'invalid_mode' supera el validador y sustituye el contenido del archivo. Se comprobó sobre un archivo temporal que pasó de ORIGINAL a CHANGED.

Acción: rechazar cualquier modo ajeno a write, append y replace_chunk antes de crear carpetas o escribir; validar los requisitos específicos de cada modo y añadir una regresión HTTP. Riesgo de integridad ante un argumento incorrecto del modelo, no una ejecución remota sin autenticación.

F3 · Media — El Service Worker excluye la aplicación publicada

En sw.js, el handler de fetch sale si url.pathname.startsWith('/zerochat'). La web de producción vive en /zerochat/: tanto /zerochat/zerochat.html como /zerochat/js/app.js quedan fuera de respondWith. Incluso /zerochat.html en la raíz coincide con ese prefijo.

Se ejecutó el handler real con eventos sintéticos: los dos recursos de producción no se interceptan; /js/app.js sí. La caché administrada por este Service Worker no puede ofrecer el offline prometido para esas rutas. La caché HTTP del navegador podría permitir cargas incidentales; no se ha hecho una prueba offline en un navegador real.

Acción: distinguir las rutas concretas del API local y el ámbito/base de despliegue. Añadir una prueba de recarga sin red bajo /zerochat/, además de la prueba del predicado.

F4 · Media — El límite de lectura no limita el trabajo ni siempre los bytes

read_file ejecuta readlines() sobre todo el archivo antes de aplicar el rango. Después trunca por número de caracteres, aunque el parámetro se llama max_bytes. Con 2.000 letras «á» y max_bytes=1024, devuelve 2.048 bytes UTF-8 de contenido. El límite de 1 MiB de HTTP solo protege la petición, no este consumo.

Acción: leer incrementalmente, respetar un presupuesto de bytes codificados y fijar una política para archivos grandes. Revisar también límites de salida de execute_command y del número de entradas de list_directory: actualmente capturan/listan sin un presupuesto equivalente.

F5 · Media / diseño conocido — El cifrado de perfiles no protege secretos frente a quien posee el archivo

profile-backup.js deriva la clave AES-GCM de una constante pública incorporada al código. El propio módulo lo reconoce. El aislamiento de postMessage corrige el destinatario de la transferencia, pero no convierte el archivo exportado en una bóveda. Cualquiera con el archivo y el código puede recuperar los secretos incluidos.

Acción proporcional: exportar sin API keys por defecto y explicitar la inclusión de secretos. Si se desea confidencialidad real del backup, usar una contraseña o un secreto del usuario. Un bloqueo de edición del perfil tampoco constituye control de acceso al secreto.

F6 · Media / mantenimiento — La base propia exige pruebas de límites reales

El parser PDF de 2.088 líneas, el parser Markdown, los adaptadores y el análisis de comandos concentran contratos complejos. El PDF es una implementación propia, no PDF.js. No hay OCR ni un corpus comparativo documentado de extracción. Orama ofrece búsqueda textual; no se ha demostrado una calidad semántica equivalente a un RAG vectorial.

Acción: mantener la ingesta ligera para documentos soportados y medirla con un corpus pequeño y estable. Ampliar formatos o extracción mediante una biblioteca especializada o servicio opcional solo si el uso lo justifica.

8. Seguridad: frontera efectiva

El backend escucha por defecto en loopback y exige token; son controles útiles frente a peticiones ajenas. El token habitual se genera con secrets.token_urlsafe(32) y se reutiliza durante el día desde config/token.json; no es estrictamente un token nuevo en cada arranque. No se observa una imposición explícita de permisos 0600 al archivo: depende de los permisos del entorno.

Las reglas de directorio residen en el navegador. Una llamada autenticada directa al backend no consulta esas reglas. Los procesos de shell y MCP tienen las capacidades del usuario del sistema. El venv es aislamiento de dependencias. La CSP admite unsafe-inline, unsafe-eval y conexiones amplias por necesidades del producto. El Worker de JavaScript es una mitigación útil para cálculos, no una garantía ante código hostil.

Esto es compatible con un laboratorio personal supervisado, si se explica. No permite presentar el conjunto como entorno confinado para ejecutar instrucciones o herramientas no confiables. No se ha demostrado una intrusión remota ni asignado una puntuación CVSS.
